# Serving and latency

Design only; nothing was implemented or measured (R-021). No latency or throughput figure appears here, and none may be claimed before E13. The agent never starts the production server (R-018): the user runs it from the run guide below.

## Target

A response within a few seconds while many requests run concurrently (R-019, decision 21). Latency and throughput are measured on the deployment, never estimated.

## Deployment model (profile value)

The deployment model is a profile value (decision 20): Qwen3.8-27B in its FP8 form, on a GPU of at least 45 GB, served by vLLM or SGLang. Facts from the notes:

| Topic | Fact | Source |
| --- | --- | --- |
| Memory | The BF16 weights do not fit a 45 to 48 GB card; the FP8 weights are about 30.9 GB on disk | [N102](note/N102-qwen3-8-27b-serving-facts.md) |
| Thinking | On by default. Turn it off per request with `chat_template_kwargs {"enable_thinking": false}`, or at the server with a default for the chat-template arguments (the server form is to confirm against the installed version) | [N102](note/N102-qwen3-8-27b-serving-facts.md), [N121](note/N121-vllm-qwen38-serving.md) |
| Sampling | The card recommends specific non-thinking sampling values, including a presence penalty. Whether that penalty harms JSON output, where keys repeat, is open: test with and without it (E11) | [N102](note/N102-qwen3-8-27b-serving-facts.md) |
| Structured output | `response_format` with a JSON schema; the grammar backend is the server's choice | [N121](note/N121-vllm-qwen38-serving.md) |
| Images | One visual token per 32x32 pixels; the default pixel cap is far above what a request needs, so the client can downscale before sending (`vision.max_image_side`: `none` by default, 1024 for experiments, decision 84) | [N102](note/N102-qwen3-8-27b-serving-facts.md) |
| Recipe | The vendor recipe was verified for text serving only. Image plus schema plus thinking off is therefore the first smoke test on the deployment (E13) | [N121](note/N121-vllm-qwen38-serving.md), [N018](note/N018-vllm-qwen35-recipe.md) |
| Throughput | No published figure for 45 to 48 GB cards. Measure it (E13) | [N121](note/N121-vllm-qwen38-serving.md) |

## What decides latency

The number of tokens generated by the two sequential model calls, the planner (S2) and the writer (S4). The candidate lookup (S1) and the knowledge assembly (S3) are lookups, not model calls. A verifier call and a repair add calls only on the paths that need them ([architecture](architecture.md)).

## Design levers

| Lever | Why | Experiment |
| --- | --- | --- |
| Thinking off on the request path | Reasoning tokens are generated tokens; turn it on only where quality gains pay for the time | E10 |
| Compact Intent IR | Short keys, no repetition of the prompt, no explanations: fewer planner tokens | E6 |
| No knowledge images in the request under `cards` | Image tokens are the largest input cost; cards are built offline (R-010) | E2 |
| Verifier inline only for the risk group, sampled otherwise | Deterministic checks run inline; the model verifier blocks the response only where the risk rules say so (R-027) | E7 |
| Merge planner and writer on the no-knowledge path | One call fewer, at the cost of the separate constraint ledger | E6 |
| One model for every role | The server batches all requests together | E13 |
| Stable prefix first | The admin system prompt and addendum lead each message, so the server's prefix cache applies. `serving.prefix_cache` records that expectation for the run guide; `enhance serve` does not read it and no wrapper setting turns a backend's cache on or off | E13 |
| Bounded queue and total deadline | Overload returns an explicit status, never a late or truncated success (R-024) | E13 |

## Embedding load

Images are embedded offline (K1). Online, only short text is embedded, so the embedder barely competes with the main model for the GPU.

## Run guide

The agent writes a run guide for the user, who starts the server. It states: the exact model repository and revision to load (`pin_required` until pinned); the server command with the thinking default, the image limit per prompt and the memory fraction, each taken from [N121](note/N121-vllm-qwen38-serving.md) and confirmed against the installed version; how to set `serving.*` and `vlm.backends` in the overlay [configs/overlays/deploy-vllm.example.yaml](../configs/overlays/deploy-vllm.example.yaml); the smoke test to run first (E13); the data to return (capability probe result, VRAM, latency under concurrency); and the reminder that the repository starts no production server.

## Not verified

Image input with this model on the deployment; JSON schema together with images and thinking off; the effect of the presence penalty on JSON (E11); the concurrency the 45 GB card sustains; every latency figure; the server flag for the thinking default.
