# K2 Observe: one image per call

**Purpose.** Read knowledge-base images once, offline, and record what each shows for each concept its folder declares, so requests use cached evidence instead of reading images (R-010, decision 13).

**Input and output.** A representative image, the names of the concepts its folder declares and the versioned facet schema, then `observations` rows per (`image_id`, `concept_id`, facet): `value`, `visibility` (`clear`, `partial`, `occluded`, `not_shown`), an optional region, plus per image a view, a quality score and its near-duplicate group. Facet groups: `identity`, `apparel`, `object`, `place`, `style`, `incidental`, `text_in_image` (text read verbatim). Schema: [contracts](../../contracts/README.md); prompt: [prompts/README.md](../../prompts/README.md).

**Method.**
- **Naming folders without a usable info file (first step, decisions 30 and 38 to 42).** A folder needs naming in two cases. (a) It has no info file, or its info file cannot be read as names (empty, undecodable, no name on line 1): K0 records it with a pending name ([K0](K0-sync.md)). (b) Its info file parses but is unclear: for every folder with a parsed info file, one text-only call of the `info_assessor` role judges whether the file gives usable concept names and returns `usable` and a reason ([info_assessment.v0](../../contracts/schemas/info_assessment.v0.schema.json), prompt `info_assessor_v0`, switch `knowledge.naming.assess_info_file`, decision 40). When the description line does not split into as many parts as there are names, the same call also assigns the text of that line to each name (decision 59) **[P]**; the implementing task adds the response field to the schema, and the line the user wrote stays in the record. A model makes that judgement, never a rule or a word list (R-015); a missing description alone does not make a file unclear, because the card supplies a summary. A file judged usable is used as written and the folder is not shown to the naming call. For a folder that needs naming, one call of the `folder_namer` role receives images of the folder plus two hints that may be wrong: the folder name and the text of the info file, when there is one. The images are drawn uniformly at random; their number is `knowledge.naming.sample_size` (default 5, the user's value, decision 39). A folder with fewer images shows all of them; a folder with no image is skipped: reported and not indexed (`knowledge.naming.on_no_images`). The drawn image ids are stored, so a resumed run reuses them. The model returns whether the folder name fits what the images show, whether the names of an unclear info file fit (they are kept when they do), the concept name or names (a hint's name when it fits; otherwise names the model proposes; several when the images consistently show several concepts), a one-sentence description for each, whether the sampled images belong together (`images_consistent`) and a short reason. When the images show unrelated subjects the model says so and the sync report flags the folder for the user; nothing splits a folder (decision 42) ([folder_naming.v0](../../contracts/schemas/folder_naming.v0.schema.json), prompt `folder_namer_v0` in [prompts/README.md](../../prompts/README.md)). No rule decides whether a folder name is related to its content: the model judges it from the images (R-015). The names carry origin `generated` (`folders.name_source` is `model`, `folder_name` when the model kept the folder name, or `info_file` when it kept the names of an unclear info file; the text the user wrote stays in the record), are used at once (decision 38), are listed in the sync report (`knowledge.naming.report`) for the user to check, and can be corrected in `kb_overrides.yaml`, which always wins. Observation needs the concept list, so this step finishes for every folder before the next one starts. Re-run rules: adding or removing images beyond a configured share re-runs naming (`knowledge.naming.rename_on_change`, `design_required`); a model-named folder that later gets an info file switches to the info file ([execution](../execution.md#what-changed-what-is-reprocessed-what-is-not)).
- **One image per model call.** Vision-language models leak information between images in one context ([N107](../note/N107-delimiter-token-scaling.md)), often fail to aggregate across images ([N108](../note/N108-mimic-multi-image.md)) and change predictions when image order changes ([N116](../note/N116-image-order-bias.md)); recording evidence per image and reasoning afterwards works better ([N109](../note/N109-evisrag.md)). Offline, the cost of separate calls stays out of request latency.
- **Folders with several concepts** get one call per image that returns observations per concept, each with an optional region when the model can localise it; whether it can is checked by a smoke test before regions are used (`design_required`).
- **Concept names only.** The observer prompt carries the concept names, not the descriptions, so editing a description never reruns observation and the description cannot prime what the model reports [P]. Text read from an image is stored as data (R-026).
- **Tiered indexing for large knowledge bases [P].** Tier 1: every image is hashed and embedded (K1). Tier 2: per folder, near-duplicates are grouped by embedding and `observe.representatives_per_folder` representatives are observed. Tier 3: the rest is observed on first use and cached: when S3 would select an unobserved image, it is observed during the request only where `rag.evidence_mode` permits live reading, otherwise it is queued in `sync_state` and observed at the next `kb sync`, which stays the only writer of the snapshot (R-014).

**Decisions and configuration keys.** `knowledge.naming.*` (`assess_info_file`, `sample_size` 5 by decision 39, `selection`, `on_no_images`, `rename_on_change` `design_required`; E17 measures naming accuracy); `vlm.roles.info_assessor`, `vlm.roles.folder_namer`; `observe.*`: facet schema version, `observe.representatives_per_folder` (`fit_from_gt`, E14), near-duplicate grouping value (`fit_from_gt`), call budget for paid backends (`ask_user`); `vision.max_image_side` (`none` by default, role override `image.max_side`, decision 84); `vlm.roles.observer`. Cache key: `image_id`, concept, observer model and processor revision, prompt revision, facet schema version ([N126](../note/N126-content-addressed-caches.md)).

**Compute.** HTTP to the `observer` backend, outside serving hours on the deployment. Cards built with the small dev model show plumbing only, never card quality (R-020). CPU tests use labelled doubles; observation quality and performance remain unmeasured.

**Depends on.** K0; K1 (image part) for observation. Naming needs only K0.

**Observation implementation (T-010 P2; PM decisions pending user review).** `k2_observe.observe_images` consumes named folder/concept rows and current K1 part-1 images, memberships and embeddings. Only `decode_status=ok` images with a valid current K1 vector are eligible; ineligible images and refused/unresolved folders are reported. It never embeds, names, publishes or invokes K3/S3. It returns updated `images.near_duplicate_group`, observation rows, checkpoint artifact references and a report.

Grouping uses connected components across the current K1 image set, with edges at cosine distance at or below `observe.near_duplicate_cosine_distance` (domain [0, 2], `fit_from_gt` until E14). Group IDs derive from sorted member content IDs and the embedder/algorithm revision. Single-link components can chain: two members can exceed the distance threshold when joined through intermediate members. Exact bounded-memory pair scans have quadratic worst-case CPU cost. Both limitations must be assessed at fit time; no performance is claimed. Restrict these global groups to each folder for selection. Order groups by their least `image_id`, choose one least-ID member per group, then fill the positive representative quota from sorted remaining IDs. Stop at `min(quota, eligible distinct images)`; zero quota is refused. The tier-3 remainder is only queued in T-010, never observed eagerly. Already completed keys remain done even if no longer representatives.

The observer gets exactly one raw image attachment as `knowledge_reference`; T-009 alone prepares it once. Its byte-for-byte system prompt treats names and visible image text as untrusted data. The separate JSON user object contains only positioned concept names and versioned facet groups. `observer_reply.v0` uses `concept_position` and contains no pipeline IDs or provenance. K2 maps known positions to code-owned IDs, rejects duplicate `(concept, facet)` entries for that image, constructs `image_observation.v0`, and validates before commit. Regions are stored when schema-valid and used by nothing. Quality is finite but has no invented probability bound. Empty observations are valid and checkpointed. Schema-invalid replies commit no observation rows; image/content/preparation/model failures fail that key and other valid images continue.

One image-call bundle/checkpoint covers the exact sorted folder concept-name set. Its content-addressed key includes image content, that name set, observer/backend/model/inference identity, processor/image policy, prompt bytes/revision and facet schema version/content. It excludes descriptions and representative quota. Every stored row repeats the full bundle key as artifact-bound `context_key`, also part of the observation primary key: an image in `{A}` and `{A, B}` contexts can retain both results without an arbitrary winner. This draft table shape requires rebuilding old observation tables, not inventing context for old rows. Replay verifies checkpoint bytes and bundle identity and reuses intact referenced results without extra calls. A crash before durable reply commit can require another external call. The stage closes only a run it owns; injected clients remain caller-owned.

The single supported phase policies are `one_image_per_call=true`, `lazy_observation_of_rest=true`, `region_output=optional`, and `facet_schema_version=image_observation.v0` when resolved. Missing, unknown or unresolved values refuse before activity; shipped fitting/design sentinels remain unresolved. Observation preflight is shared by command loading and standalone entry. Work is submitted in batches bounded by the observer backend's configured `max_concurrency`; the shared transport also enforces each actual backend's limit. Fatal batch errors cancel and await sibling work before writer/client teardown. Multi-image role demands accept only tuples/frozensets of exact code-owned capability names, refusing unknown names before proof/spend. Repeated direct backend starts can extend cached proof without a new allowance; an explicit backend-only supplied plan still acts as explicit proof demand without `require`. Naming draw paths admit only `.bin` at the storage boundary.

**Naming implementation (T-010 P1).** `k2_naming.name_folders` consumes K0's naming handoff plus its image and membership rows and returns the updated naming tables, a report and checkpoint references. It never publishes or runs observation/cards/aliases/indexing. A parsed usable no-image folder can still be assessed and kept; an unclear parsed file with no eligible images retains its declarations and curated descriptions with `name_source=info_file`, no namer call, and a `retained_declared_folders` report entry. Other naming candidates with no eligible image are skipped/reported. Explicit failed K1 decode statuses are excluded, while null K0 statuses pass to T-009 preparation. An invalid draw fails that folder without silently replacing an image. Generated names containing CR or LF are refused before trimming. Other generated names use K0's structural token trim, preserving accepted Unicode separators such as U+2028; a blank result or a name containing `knowledge.concept_separator` fails only that folder. Trimmed names are used in identities, checkpoints, tables and reports. Model payloads contain ordered zero-based `image_labels`, never folder ids or image hashes; internal code retains their mapping to the sampled images.

Draws use OS randomness over distinct content ids, with no seed key. The draw commits before the naming call; resume preserves the ordered sample. Adding/removing more than `rename_on_change` of the saved candidate set reruns naming: `(added + removed) / previous_count`, with strict greater-than comparison. A missing sampled id redraws the whole sample and is reported. A private head locates the current content-addressed draw; snapshot callers may reference returned artifacts, never private heads. If GC removes the head, naming recovers from the newest snapshot by its stored `created_at` in the registry; no new clock or mtime read. A public storage reader supplies live artifact references and their manifest hashes/sizes, indexed once per run. Compatibility includes folder identity, sample size and selection. The first snapshot with compatible draws must contain exactly one; several compatible draws cause `baseline_ambiguous` and a fresh draw, without guessing or falling through to an older snapshot. Manifest and checkpoint checksums and sizes must agree. Recovery and absence are reported as `baseline_recovered` and `baseline_missing`; these diagnostic redraw entries do not necessarily mean another model call. Immutable content-derived `k2_redraw` checkpoints preserve causes across interruption and replay and are returned for snapshot references. An ambiguous draw key also includes the conflicting baseline keys so a fresh draw cannot overwrite their artifacts and interrupted work resumes consistently. No referenced draw is rewritten. K0 owns folder identity, so a folder rename may redraw. Completed intact replies need no extra call; an interrupted in-flight request without a committed reply may be retried. The threshold stays `design_required`; tests alone use labelled concrete values.

The production local multi-image probe plan builds PNGs with one and two black circles and asks for ten times the first count plus the second count (12, then 21 when swapped). It uses the requesting role's backend model and token cap. After validating its configuration and drawing the sample, naming explicitly requests `multiple_images` through the keyword-only `for_role(..., require=('multiple_images',))` argument when its pending call has more than one image. The generic client reads no naming configuration; an unrequested role adds no pair. The client checks that the role has a declared image source and owns the backend receiving the proof. Actual multi-image calls also state this demand. A later role needing missing evidence extends the backend's cached proof even when another role bound first, preserving its other evidence. Initial probes and lazy extensions share one backend `probe.max_requests` allowance; binding another role never resets it. Known negative proofs and attempted incomplete/failed extensions are not retried on later binds. Explicit backend-only plans remain supported. Missing, incomplete or negative proof refuses a multi-image naming call; ordinary image/output capabilities still require their own evidence. The production pair sends model id and token cap without the role's generation settings, and is attached only to that role's configured backend; conservative refusal on an unproved fallback backend remains known behavior. P1 tests use labelled doubles, not live model evidence. Overrides implement only the four documented keys ([contract](../../contracts/README.md#info-file-and-knowledge-base-input)); no folder rename override exists.

**Failure modes.** The model names a folder wrongly and every image inherits the wrong concept (mitigation: the sync report lists every model-named folder, `kb audit` samples them, the override file corrects them); two folders get different generated names for the same thing, so they do not merge into one concept (mitigation: K4 alias collisions and the lint report surface likely duplicates; a person merges through the override file) **[P]**; a wrong observation spreads to every request that uses the card (mitigated by K3 lint and the E16 audit); hallucinated facets for occluded parts (visibility is recorded per facet); a concept the model does not recognise in a multi-concept image (recorded as `not_shown`); text in an image that reads as an instruction ([N131](../note/N131-image-prompt-injection.md)).

**Experiments.** E17 (naming accuracy), E14 (representatives per folder), E16 (card audit), E2 (cards versus live reading), E12 (dev smoke with image input and schema).
