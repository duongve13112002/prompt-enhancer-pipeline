# K1 Embed: images and concept text

**Purpose.** Give every image and every concept a vector, so K2 can group near-duplicates and pick representatives, S1 can find concepts described indirectly, and S3 has a fallback for attributes outside the facet schema. Embedding every image (part 1) is the cheap first tier of indexing ([K2](K2-observe.md)).

**Input and output.** K1 has two parts. Part 1 (after K0, before K2): new or changed `image_id`s from K0. Part 2 (after K3 and K4): the text of each concept (name, description, aliases from K4, card summary from K3). Output: `image_embeddings` and `concept_text_embeddings` as Arrow, each row keyed by content plus embedder revision (R-016, R-017). Image metadata (format, dimensions, decode status) goes to `images`.

**Method.** Part 1: decode each image once, record dimensions, embed with the configured embedder; the embeddings group near-duplicates, and those groups let the naming step of [K2](K2-observe.md) choose a varied subset of a folder without an info file. Part 2: embed concept text, which includes the card summary and aliases and so waits for K3 and K4, with the same encoder so text and image vectors share a space. Concept text is re-embedded when the name, description, aliases or card summary change.

Online, S1 embeds only short text (the prompt and its segments), so image embedding never runs on the request path. One embedding space per snapshot: vectors from two embedders are never mixed.

**Decisions and configuration keys.** `embedding.*`: the backend (`embedding.backend` names a local `vlm.backends` entry with an `endpoints.embeddings` route; its `model.revision` must equal `embedding.revision`, `pin_required`), the request layout (`embedding.request.shape`, `image_instruction`, `extra_body`, `text_template`, `design_required` until the live smoke proves them, T-008), the dimension and how it is reached (`embedding.dimension`, `fit_from_gt`, E5; `embedding.dimension_mode`: `native`, `request_field` or `client_prefix_l2`) and the batch size (`embedding.batch_size`, `deploy_required`). Devices are not a client key: the embedding server's launch places the model (`runtime.gpus`, `runtime.vram_budget_gb`, the `gpu-live-run` plan; T-008 Q2). Images travel as data URIs (`vision.transport: data_uri`, the only accepted value). Every image goes through the shared client-side resize of `vision.max_image_side` before embedding (`none` by default, decision 84, [VLM_CALL_RULES](../rules/VLM_CALL_RULES.md) rule 7). The embedder is chosen by E5 on the user's knowledge base, not from published leaderboards, because published figures are measured on other data. Candidate embedders, their licences and their text-length limits are in the references.

**Implementation (T-008).** `prompt_enhancer.k1_embed`: `embed_images` (part 1) takes the K0 handoff, reads each image read-only with no link on any path component and checks its bytes against `image_id`, decodes it once (format and pixel size of the stored file before any orientation go to `images`; a TIFF gives its own size tags), prepares it with the shared resize and embeds it in batches over HTTP. `embed_concept_texts` (part 2) is the interface K3 and K4 will call; it is tested with fixtures. Each input is one checkpoint artifact keyed by its content hash plus the embedder revision, the request settings and the image settings; a rerun skips finished keys, and an artifact a live snapshot references is reused (`REUSED_REFERENCED`) rather than recomputed, because server output is not guaranteed bit-identical. Refusals of an image by policy are stored (`decode_status`); unreadable or changed sources and HTTP or response errors fail the item and are retried at the next sync. Any error the decoder raises on a file's bytes makes that image `undecodable` (stored, not retried); a settings or encoding fault stops the stage. Before any read or request, both entry points check every key K1 reads against that key's node in the configuration schema, with exact integers and finite numbers, the same check `kb sync` runs at load; each timer must also convert to a finite float (the AnyIO and asyncio clocks raise on the rest), and `vision.format` must name an encoder installed in Pillow, used as given with no fallback to the source format, that registers an `image/` media type (`Image.MIME`); the data URI states that registered type, not the encoder name (JPEG2000 is sent as `image/jp2`), and the loader and both standalone entry points refuse an encoder without one before any read or request. K1 returns its tables and never publishes.

**Compute.** GPU on the dev machine and the deployment, batched; the embedder can share the GPU with the serving model only within the VRAM budget of [PLATFORM_GPU_RULES](../rules/PLATFORM_GPU_RULES.md). Nothing measured; the live smoke is a separate `gpu-live-run` step.

**Depends on.** Part 1: K0. Part 2: K3 and K4.

**Failure modes.** Text longer than the encoder's token limit is truncated silently (check per encoder); weak coverage of a language or script in the encoder (measured in E1 and E5 per language and script); a changed embedder without a new index (prevented by keying on the revision).

**Experiments.** E5 (embedder comparison), E1 and E4 (contribution of dense search to linking).
