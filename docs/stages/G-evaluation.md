# G Evaluation: scenarios from the knowledge base

**Purpose.** Measure the pipeline and fit every `fit_from_*` value on data it did not produce. No gold prompts exist (R-023, decision 22), so agents generate scenarios from the user's knowledge base; answer keys come from the folder declarations. Agent-generated scenarios are **silver**; real user prompts become **gold** when the user supplies them. The runner and the score import are built (below); no scenario set is accepted and nothing is measured yet; layout: [evalset/README.md](../../evalset/README.md).

**Input and output.** A published snapshot and its folder declarations, then `eval_scenarios` (prompt, task, source image for edit, scenario kind, language and script), `eval_labels` (the answer key) and `eval_results` (per scenario and metric), plus a fitting report per value.

**Method.**
1. **Generate (`eval build`).** The orchestrator has agents, and the `scenario_generator` role, write prompts in every input format (tags, prose, structured, mixed, R-003) and in several languages and scripts, covering: exact names; paraphrased or indirect mentions built from a description; family mentions (a general mention that several concepts fit); negated mentions; unknown names absent from the knowledge base; multi-concept prompts; edit instructions over example images.
2. **Answer keys** come from the declarations, not from a model's judgement: the concept a scenario was built from; `family` with the valid members for a general mention; `NEGATED_BY_USER` for a negated concept; `no_match` for an unknown name; for edit, the targets, delta and preserve list the scenario specifies.
3. **No self-grading.** A scenario generator never evaluates scenarios whose key it wrote; another agent or a model of another family scores them.
4. **User review.** The user reviews a sample of scenarios and keys before any value is fitted.
5. **Splits** into `fit` (used to fit values) and `test` (used to report) by concept, so a concept is never in both. Sentinels are fitted on the `fit` split from runs that use the deployment's models; runs on the dev machine never fit a sentinel (R-020). The split is unrelated to the dev machine.

**Metrics.** Shortlist recall at the shortlist size; resolution precision and coverage; no-match accuracy; family picks that avoid `conflicts`; constraint survival per type (R-001); leakage and under-editing rates; card fact and label precision; status correctness (a truncated output is never `success`); latency and throughput on the deployment only (R-019). Every metric is reported with its confidence interval and its denominator, never as a point value alone.

**Runner (`eval run`, `eval import`; T-016 phase 4, decision 154).** Built and tested with labelled doubles only; nothing was run on the real draft set or a live model.
- **Input.** The draft `scenarios.parquet` is read through an adapter that keeps the five `draft_*` columns and all multilingual text verbatim (they are never stored in `eval_scenarios`, whose schema is closed). Every record and every concept or image id is checked before the first model call; a refusal names a position and a field, never a value. Edit source bytes come from the snapshot by content id (retained originals), or from `--source-images` for the retrieval-off variant, and are checked against the image id.
- **Execution.** One owned `Pipeline` per variant (the off variant is a copy of the profile with retrieval off, so it never opens a store or a gateway, R-009); a bounded queue fed by the streaming adapter, `evaluation.run.max_concurrency` scenarios at most in flight in total (decision 149), a single writer for every append and `after_delivery`. A failed scenario writes a marker (`incomplete/`, disposition `failed`) and is counted as `failed`; a scenario the pipeline refused for trace capacity (`LifecycleFull`; no setting guarantees it cannot happen) writes a `not_run` marker with reason `trace_capacity`, no row, and is counted in the summary (`not_run_reasons`); the next invocation retries both kinds and nothing else, with no retry loop inside a run. **One run at a time:** `eval run` takes the exclusive run lock (`eval/runs/<run_id>/run.lock`, the project lock primitive, non-blocking) before its first write and keeps it until the invocation ends on every exit path; a second `eval run` of the same identity, or an `eval import` of that run, is refused at once with no model call and no side effect, so a repeated `(run_id, scenario_id)` row cannot be written. Rerun only after the first process has ended. Every sidecar write (manifest, attempts, summary, pack, key, imports) happens under that lock; every reader that counts rows (summary, pack writer, import) refuses a repeated key. A run directory is named by a hash of the set, snapshot, configuration, models, prompts, profile, variants and split; a directory with another manifest is refused, never overwritten. The blinding seed is not part of that hash.
- **Metrics (structural, label `structural`).** Schema validity, envelope status, exact literal constraints (the literal span as a verbatim part of a text output). Stays `not_run`: the ID-level link check (reason: trace row unavailable, because no bounded trace read by `trace_id` exists), every semantic metric until scores are imported, and every confidence interval (the interval method is not approved).
- **Judge pack and import.** The pack lists per scenario the prompt, the answer key, the rubric dimensions that follow from the key's structure, and the outputs under blind labels `A` and `B`; it holds no status, warning, retrieval state, attachment, trace id or variant. **Limit of the blinding (PM decision, accepted by the user in decision 170):** it protects the comparison between the two variants of one scenario. A two-output item shows the outputs in an order drawn from the blinding seed and carries nothing that tells the labels apart; a single-output item (a retrieval-off record, or any run with `--variants record`) shows its own variant and its `kind` can reveal it, so such a pack is no blinded on-against-off comparison. A new seed writes a new pack (another `pack_id`) with no model call. `eval import` refuses unknown, duplicate or missing scenarios and ratings, values outside `evaluation.judge.score_min..score_max`, unknown fields (no free text exists) and scorers of one family or of a family under test; disagreement is any difference (no threshold). The pack is streamed line by line on import and written only if it fits `evaluation.run.max_sidecar_bytes` (a validated profile value, sentinel `deploy_required`; it bounds every sidecar read and the pack and key writes). Exit codes: 2 only for a refusal before any side effect, 1 for a failure after one (a refusal after the first written result, a `StorageError`, failed units). Imported scores are pilot evidence labelled `agent_judged`; they never reach thresholds, calibration or `eval fit`. The rubric `prompts/eval_rubric_v0.txt` is a neutral draft (PM decision, accepted by the user in decision 170) used only for these judge packs, never by the pipeline.

**Experiments.** Each experiment decides one design question and fits the sentinels named; "the interval" means the confidence interval of the metric on the test split.

| Exp. | Decides | Accepted when | Fits |
| --- | --- | --- | --- |
| E1 | linking quality per language and script | the chosen settings maximise resolution precision at the coverage the user accepts | `candidates.*` shortlist size, fusion weight, n-gram length (`fit_from_gt`) |
| E2 | `rag.evidence_mode` | `cards` is kept unless another mode is better beyond the interval | `rag.evidence_mode` |
| E3 | reranker before resolution | a reranker is added only if it improves E1 beyond the interval | `candidates` reranker switch |
| E4 | which candidate sources run | a source stays when removing it lowers shortlist recall | `candidates` sources |
| E5 | the embedder | best E1 on the user's knowledge base | `embedding.*` (then `pin_required`) |
| E6 | planner and writer split or merged without knowledge | merged only if no constraint metric drops | `planner`, `writer` merge switch |
| E7 | verifier gating | risk-gated is kept if it misses no more failures than always | `validation` gating and sampling share (`fit_from_pilot`) |
| E8 | `verbalize` versus `attach` | measured on downstream images when the user supplies an image model; before that, task T-034 renders with Codex image generation as a stand-in to test the flow only (decision 47) | informs the user's `edit.attach_kb_reference_images` choice |
| E9 | the scope matrix | changing out-of-scope content of knowledge images changes no output | validates `assembly.scope_matrix` |
| E10 | thinking on or off | on only if quality gains outweigh measured latency | `planner`, `writer` thinking |
| E11 | presence penalty with JSON | the value with no schema failures and no quality loss | `planner`, `writer` sampling |
| E12 | dev smoke | image input, JSON schema and thinking off work together on the dev server | gate only |
| E13 | latency and throughput under concurrency | meets the user's target on the deployment | `serving.*`, `runtime.*` (`fit_from_bench`) |
| E14 | representatives per folder | the smallest number whose card precision matches observing all images | `observe.representatives_per_folder` (`fit_from_gt`) |
| E15 | quantisation on the dev machine | reports whether a higher quantisation changes the rate of invalid outputs on the dev machine; information for the user, who chooses the dev file (decision 20) | nothing: the dev file is the user's choice and is not fitted |

| E16 | card audit | fact and label precision on a human-checked sample meet the user's bar | `cards.min_visible_images`, low-diversity value (`fit_from_gt`) |

**Decisions and configuration keys.** `evaluation.*` (scenario counts per kind, split seed, call budget `ask_user` for paid backends), `vlm.roles.scenario_generator`.

**Compute.** Agent sessions and model calls; quality runs on the deployment model, plumbing on the dev machine (R-020).

**Depends on.** K0 to K5, P; every online stage is under test.

**Failure modes.** Scenarios that only echo the generator's style (the user's review and gold prompts later correct it); keys that are wrong when a folder's images do not show its concepts; too few scenarios per language for a useful interval.
