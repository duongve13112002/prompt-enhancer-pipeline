### Ranked questions with proposed answers

1. **HTTP layer for `enhance serve`:** standard library only; `POST /v1/enhance` (the `request.v0` schema), `GET /health`, and an attachment download route; HTTP 503 on queue overflow.
2. **`enhance once` input and output:** `--request <file>` validated against `request.v0` (prompt-only flags optional); pure envelope JSON on stdout; attachments written under a configured or given output folder inside the project (AGENTS.md section 6).
3. **Concurrency and shutdown:** bounded by `serving.max_concurrency` and `serving.queue_limit`; on a stop signal, stop accepting, finish or cancel in-flight requests within the configured deadline, `await pipeline.close()`, exit with nothing left running.
4. **`eval *` scope:** see PM review.
5. **Run guide:** a new `docs/` guide: preflight (VRAM baseline), model servers, `kb sync`, `profile check`, `enhance serve`, smoke requests for generate, edit and retrieval off, teardown with VRAM back at baseline, and a result template the user pastes back.

### Unknowns, failure modes and corrections to the scout

All code claims in this section are **source-verified**; document requirements are **documented**; designs and unresolved choices are **proposals**, not measurements.

1. **The command inventory is incomplete, even for an existing command.** `__main__.py:15-46` serves only `kb sync` and `kb audit`. The sync path is `k0_sync.sync_config` -> `asyncio.run(kb_sync.sync_knowledge)` (`k0_sync.py:119-124`), not a direct CLI call to a `kb_sync` function. `docs/execution.md:18` also promises `--only <folder>`, but neither parser nor coordinator accepts it (`kb_sync.py:90`). Subsetting a full-snapshot sync risks treating excluded folders as deleted. `kb status` promises pending changes although its documented inputs and `COMMAND_READS` only include store/lock values (`docs/execution.md:17`; `config.py:58`). Existing store readers expose snapshots/current, not a pending-source-change or aggregate status API (`storage/store.py:447-452`, `:485-489`). These need a scope decision, not fabricated counts.
2. **The scout overstates existing serving validation.** The schema accepts zero concurrency and zero deadline and has no host/port (`contracts/schemas/enhancer_config.v0.schema.json:5206-5293`); `enhancer_config.v1` inherits the serving section through the loader's local-reference expansion (`config.py:1748-1767`). Consumed sentinels are refused, but useful positive bounds/cross-field checks must be added. A scoped search of `src/prompt_enhancer/*.py` found no `prefix_cache` reader; the setting currently describes external-server configuration (`configs/enhancer.example.yaml:407`; `docs/serving.md:37`). It must receive an explicit owner rather than being silently read and ignored. No web framework is declared (`pyproject.toml:8`). The existing embedding server is a useful bounded-transport reference, not a drop-in pipeline server (`embed_server/server.py:10-21`, `:452`, `:811`).
3. **Delivery and shutdown are separate from generation.** `PipelineResponse.after_delivery()` must follow successful delivery (`pipeline.py:28-35`); the pipeline does not call it for ordinary callers. `Pipeline.close()` cancels maintenance, closes the lifecycle and synchronously expires traces (`pipeline.py:123-135`). Disk writes that exceed `trace.drain_timeout_s` are recorded and then awaited; executor shutdown joins them (`response_lifecycle.py:137-144`). Thus T-015 does not promise a hard wall-clock shutdown bound. Admission, queued requests, slow HTTP readers/writers, console output and thread joins require their own blocking-call inventory. Cancelling an await does not establish that an owned thread exited.
4. **Attachments are not paths or URLs in the response contract.** They are metadata plus separate bytes (`envelope.py:35-49`; `pipeline.py:62-74`, `:236`). Metadata cannot simply gain an output-path field. T-015 holds the pinned snapshot for attachment retention but does not persist a CLI output directory or expose a download service. Trace expiry releases holds (`trace_store.py:33-35`, `:48-71`). Windows filenames cannot use the raw `sha256:` image ID. Copy publication, download expiry, delivery failure and path/link containment need tests through anchored storage (`storage/_anchored.py:60-94`), including the scanner guard learned in `tasks/LESSONS_LEARNED.md:78`.
5. **The T-003 draft is not an executable request set or a complete scoring contract.** It was accepted as a silver sample, built before a snapshot (`tasks/active/T-003-evaluation-set.md:16`, `:44-60`; decision 65 at `tasks/archive/decisions-054-066.md:18`). The shared project's read-only `data/eval/draft-2026-11-14/` exists; this worktree has no local copy. `scenarios.v0.jsonl:1` contains concept/constraint keys; `:36` identifies an edit source by image/folder IDs, not base64; `:51` has no retrieval-switch field despite being a `rag_off` scenario. `request.v0` instead accepts base64 source bytes and typed overrides (`contracts/schemas/request.v0.schema.json:7-13`). The loss of family, edit and retrieval information in v0 is already documented (`T-003-evaluation-set.md:59`). Do not infer a retrieval switch from prompt text or use the lossy JSONL projection as the pilot's sole input.
6. **Scoring requires decisions that the scout did not identify.** G requires independent semantic scoring, concept-separated splits, denominators and confidence intervals (`docs/stages/G-evaluation.md:9-14`); it gives no complete per-metric matching algorithm, interval method/confidence level, independent scorer binding or pilot snapshot-binding format. `eval_results` has a JSON `metrics` column but no dedicated snapshot/trace columns (`storage/tables.py:124-135`), and `DataStore.append` alone is not a resumable runner (`storage/store.py:1358-1377`). Treating the verifier under test as its own evaluator, scoring prose with word lists, fitting on dev results or calling an unconfigured paid evaluator would violate the requirements.

### Design after approval

- **Entry points and input.** Extend `python -m prompt_enhancer` with the documented groups; keep the existing module name and separate embedding CLI. Require `--config`, permit the existing single `--overlay`, and add a validated `--project-root` to support a deployment root and subprocess fixtures (the embedding CLI already has it: `tests/test_embed_server_cli.py:92-104`). Default root remains the existing source-derived project root (`__main__.py:32`), an artifact-bound rule, not a new machine path. Resolve configuration/request/set paths under that root. `enhance once --request <file>` is the sole request syntax proposed; no optional prompt/task flags to create a second interpretation. Decode strict UTF-8/JSON, reject duplicate keys, nonfinite/overflowed numbers, malformed roots/unknown fields and invalid edit/source combinations with field/argument/line diagnostics without echoing private payloads; reuse `model_json.strict_json` (`model_json.py:6-25`) and `request.v0`. Preserve prompt bytes after UTF-8 decoding and the admin system text; no natural-language interpretation in wrappers (R-001/R-004/R-026). File/HTTP byte and parser resource limits are in the configuration table, not guessed defaults.
- **Dispatch and diagnostics.** Route parsed commands to production APIs, with diagnostics on stderr and JSON only on successful stdout delivery. Proposed new-command exit codes: 0 for completed operation/delivery (including an honest non-success pipeline envelope), 1 for operational failure, 2 for argument/configuration/input refusal or deliberately unavailable command. Document envelope status separately so a failed/degraded result is never described as successful enhancement (R-024). Preserve existing `kb sync/audit` exit behavior to avoid an unrelated compatibility change: current caught configuration errors exit 1 (`__main__.py:44-46`); the scout's universal exit-2 claim was incorrect. The separate embedding CLI does use exit 2 (`tests/test_embed_server_cli.py:87-104`). Tests pin both behaviors and failure before side effects. Profile-check golden failures are operational exit 1; unconfirmed/invalid profile inputs are refusal 2.
- **Profile/store wiring.** Own writer contexts for rollback/GC and snapshot leases for show/status. Do not use a writer for read-only status or invent source-change counts. Register obtains the production bound `manifest_drafter` and closes its owner (`model_client.py:179`, `:218`, `:251`); check owns `Pipeline` plus `GoldenAdapter`. Because `profile check` currently declares only profile/lock reads (`config.py:73`), the CLI must additionally run request-command preflight before constructing the golden pipeline, including version 2, actual roles, conditional retrieval and lifecycle reads. Neither command auto-confirms conflicts or bypasses activation checks.
- **HTTP surface (proposed).** `GET /health` reports service readiness only, without inference or a KB scan; `POST /v1/enhance` accepts one `request.v0` JSON body and returns `response_envelope.v0`; the attachment route is conditional on Q3. Malformed/invalid transport input returns structured 400/413/415 as applicable; unsupported route/method returns 404/405; full admission or trace capacity (`LifecycleFull`, `response_lifecycle.py:7`, `:33-35`) returns 503 before a model call; service deadline returns 504; transport/storage delivery failure returns 500. Completed pipeline results retain their own honest status in a 200 envelope. Transport error JSON is distinct from the S6 envelope and never fabricates its required trace ID. No health, overload or invalid-request path may start model services or paid calls.
- **Admission, deadlines and delivery.** Hold at most `serving.max_concurrency` active generations and `serving.queue_limit` waiting requests; bound accepted connections/body reads independently so admission is not just a semaphore over unlimited tasks. Service total deadline starts at admission, includes queue time/body/output work and wraps the pipeline's independent `runtime.request_deadline_s`; neither is silently replaced. Disconnect removes queued work or cancels active work, releases admission and follows T-015 cleanup. Use a single owned `async with Pipeline(...)`; call `after_delivery()` only after bytes have been written/flushed by the transport, or stdout and attachment publication succeed for once. A flush means local transport delivery, not proof the remote application consumed the body. On failure leave the ticket unacknowledged so lifecycle close records `delivery_unacknowledged` (`response_lifecycle.py:126-130`). Restore signal handlers and account for every task/thread/socket on all exit paths.
- **Cross-platform stop.** Main-thread `signal.signal` handlers for Ctrl+C and SIGTERM where supported, plus SIGBREAK on Windows, signal the owner loop/event; avoid assuming `loop.add_signal_handler` works on Windows. Existing project pattern: `embed_server/__main__.py:181-193`. Tests must distinguish cooperative Python SIGTERM handling from Windows `TerminateProcess`; a forced kill is teardown fallback and cannot count as a clean-stop test. Hidden child processes use `CREATE_NO_WINDOW`, `-X faulthandler`, bounded waits, recorded PIDs and finally cleanup. Read the installed stdlib behavior before choosing the exact Windows signal-test mechanism.
- **Evaluation (conditional on Q1).** Require explicit set/profile/snapshot inputs; validate set provenance and all records before spending calls, adapt draft fields structurally and preserve multilingual data. Bind edit source bytes from the explicitly selected snapshot by content ID, not the mutable source tree. Keep independent pipeline lifecycles for retrieval on/off because changing `rag.enabled` inside an existing owner is refused (`pipeline.py:144-150`); an off record must never open a gateway/store or an on pipeline merely to load its source image. Require a separately provided contained source-image fixture/input for an off edit if needed. Use deterministic content/config/tool/model keys and existing anchored data storage to resume at the first missing result without duplicate `(run_id, scenario_id)` records; a random new run ID alone is not resume. Put set/snapshot/trace/scorer provenance inside validated result metadata/metrics or an explicitly approved sidecar; do not silently add table columns. Persist summary counts for completed/failed/skipped/not_run independently. Metric definitions and schema extensions remain Q1, not implicit implementation decisions.
- **Run guide outline.** New `docs/deployment-run-guide.md`, linked from execution/serving: CPU environment and artifact/revision/hash preflight; resolve every consumed sentinel with a validated base/overlay; GPU/VRAM-holder baseline and authorized call budgets; user-started pinned VLM/embedder commands with installed-version checks; `kb sync --plan`, sync/status/show, explicit admin confirmation and `profile check`; generate/edit x retrieval on/off examples; service health/overflow/attachment/status expectations; named-set pilot and result locations; resume/rollback/GC; Ctrl+C/SIGTERM teardown with owned PIDs, ports and VRAM back at baseline; a paste-back report for environment, commands, probes, statuses, failures and measurements. Do not choose models, sampling, thresholds or deployment capacity, infer performance, start production services, or print secrets (R-018/R-020/R-025). Version-specific server commands that cannot be verified stay explicitly unresolved, not advertised as runnable evidence (`docs/serving.md:44-50`).
