## Brief header

- **Goal:** the orchestrator can run the test suites on GitHub Actions, on the latest Ubuntu and Windows runners, for a pushed commit. The repository is public only for the run and private again when the run ends, green, red, cancelled or timed out ([docs/ci.md](../../docs/ci.md), decisions 26, 77, 111, 112).
- **Phases** (decision 111):
  - **Phase 1 (now):** work items 1 to 4.
  - **Phase 2 (after T-026 is integrated):** work item 5. Both T-026 and item 5 change the SessionStart hook.
- **Work items:**
  1. **Workflow.** `.github/workflows/ci.yml`:
     - a matrix of `ubuntu-latest` and `windows-latest`;
     - triggered by `workflow_dispatch` only (no `push` or `pull_request` trigger), so a push never starts a run while the repository is private;
     - runs the pipeline suite (`tests/` with `PYTHONPATH=src`) and the tooling suite (`tools/agent-workflow/tests`);
     - installs the CPU dependency profile only ([dependencies](../../docs/dependencies-and-environments.md));
     - no GPU, model downloads, secrets or paid calls;
     - pins each action to a full commit SHA, with the version in a comment, and asks for the least token permissions (`contents: read`).
     The tests that are known to fail on Windows are listed in `tasks/STATUS.md`. Report how CI treats them. Never skip or weaken a test to make CI green.
  2. **Visibility-window tool**, a tracked Python script such as `tools/agent-workflow/ci_window.py`, run by the orchestrator only. It follows the six steps of `docs/ci.md`:
     - **Preconditions:** a clean tree; the local head equal to the remote head; the pre-publication check; a secret scan over the commits to be exposed.
     - **Run:** record the visibility, switch to public, dispatch the workflow on that commit, wait with a time limit.
     - **Always-run return:** switch back to private in a `finally` path that also runs on an interrupt, then verify the visibility.
     - **Result:** a small JSON report under `runs/` or `.tmp/`.
     Every value that may vary is profile or configuration, refused when absent (AGENTS.md section 5): the time limit, the poll interval, the workflow file, the branch, the report path. It calls `gh` as a child process with `CREATE_NO_WINDOW` on Windows.
  3. **Tests** with a labelled `gh` double (no network). They cover:
     - each refusal: a dirty tree, an unpushed head, a tracked forbidden path, a secret-scan hit, missing configuration;
     - the return to private after green, red, a timeout, a dispatch failure and a raised exception;
     - a failed final verification, reported loudly;
     - an already-public start, which leaves the repository as found and says so.
     Mutate the changed lines (about 3 to 10 mutants).
  4. **Docs.**
     - `docs/ci.md`: from "design" to how to run it. Replace each "to verify (N134)" with the primary-source quote and URL, or keep it labelled.
     - `docs/test-plan.md` where CI is named.
     - Propose the open point "Windows in every window or only at feature completion" with the measured run time, if one exists. Otherwise leave it as a proposal.
  5. **Phase 2.** A session-start check that the repository is private, through the SessionStart hook (`session_context.py` or the hook T-026 leaves). It is a read-only `gh` query that warns loudly when the repository is public, and when `gh` is missing or not logged in it says that it could not check.
