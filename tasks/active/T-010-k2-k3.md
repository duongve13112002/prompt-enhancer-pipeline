## Goal

Implement K2 and K3 as [docs/stages/K2-observe.md](../../docs/stages/K2-observe.md) and [docs/stages/K3-cards.md](../../docs/stages/K3-cards.md) describe, in three phases on one worktree. Each phase is reviewed and accepted before the next starts.

- **P1, K2 naming (decisions 30, 38 to 42, 59; E17):**
  - `info_assessor`: one text-only call per folder with a parsed info file, under `knowledge.naming.assess_info_file`.
  - The response field that assigns the description line to each name when the counts differ (decision 59). Add it to `info_assessment.v0`.
  - `folder_namer`: for the folders K0 left pending or the assessor judged unclear. It draws `knowledge.naming.sample_size` images uniformly and stores the drawn ids, so a resumed run reuses them.
  - Write `folders.name_source`, `concepts` and `folder_concepts` with origin `generated`.
  - `kb_overrides.yaml` always wins.
  - Include the sync-report entries.
- **P2, K2 observation (R-010, decision 13, decision 84):**
  - Choose `observe.representatives_per_folder` representatives per folder, using K1 near-duplicate groups.
  - Make exactly one image per `observer` call, through T-009's `prepare_image`.
  - The prompt carries concept names only; text read from an image is data (R-026).
  - Validate each response against `image_observation.v0`.
  - Write `observations` rows and a `sync_state` checkpoint per cache key (`image_id`, concept, observer model and processor revision, prompt revision, facet schema version).
  - Queue the tier-3 images.
- **P3, K3 cards and `kb audit` (decisions 10, 16):**
  - Aggregate per concept across folders.
  - The `card_builder` model groups equivalent values; no string rules.
  - Assign stability labels by invariance under variation, never by majority vote.
  - Write the card summary, the `cards` rows on `concept_card.v0` and the lint report.
  - `kb audit` samples model-named folders and cards for the admin.

## PM decisions before P1 (user away; conservative and reversible; PM decision pending user review)

1. **Overrides:** implement only the four documented `kb_overrides.yaml` keys (`concept_type`, `aliases`, `facts`, `suppress`; `contracts/README.md:124`), with a schema and a hash.
   - No key renames a folder, so the report says so; a folder rename override is a question for the user.
   - An override naming an undeclared concept creates nothing and is reported in lint.
   - A `facts` entry that names no facet goes to `curated_statements` only.
2. **Orchestration:** K2 consumes K0's `handoff['k2']` and returns a report dict. Publishing the K0 to K3 snapshot and the persisted sync report stay with a later task: like K0 and K1, K2 and K3 never publish. P3 wires `kb audit` read-only on a pinned snapshot and leaves `kb_store` as found.
3. **Identifiers:** pipeline-owned identifiers are written by code and never read from a model reply. These are `image_id`, `concept_id`, `folder_id`, `sampled_image_ids` and `origin`/`model_revision`. The prompt uses positional labels that code maps back; a reply whose labels fall outside the set commits nothing.
4. **Sentinels:**
   - `rename_on_change`, `representatives_per_folder`, `facet_schema_version` and `min_visible_images` stay sentinels and are refused at start.
   - The two keys the stage docs name but the schema lacks are added as `fit_from_gt`: the near-duplicate grouping value and the numeric low-diversity value.
   - Tests use labelled test-only values.
   - The `rename_on_change` formula is `(added + removed) / previous count` over the drawn-from image-id set, with no default.
   - `facet_schema_version` names the contract version (`image_observation.v0`). There is no hand-written facet list: a model chooses `facet` within the seven groups.
5. **The draw:**
   - It is committed as its own artifact before the call, with an injectable RNG (production uses system randomness, so no seed key).
   - `sample_size: 0` is refused for naming.
   - If a stored id vanished, the whole sample is redrawn and the redraw is recorded.
6. **`folder_namer` with more than one image needs the `multiple_images` capability.** T-010 adds the probe plan that proves it. A backend without that proof is refused with `CAPABILITY_UNAVAILABLE`, and nothing commits.
7. **Observation:**
   - The cache key includes the calling folder's exact concept-name set and the role's image settings.
   - Representatives are chosen per folder, with sorted `image_id` as the stated tie-break.
   - The tier-3 rest is only queued, never observed in T-010.
   - Duplicate facets in one reply reject that image only.
8. **Cards:**
   - The `card_builder` model sees a model-facing schema: value groups, summary and lint findings. Labels and counts are computed by code.
   - `seen_count` counts the images where the facet's visibility is `clear` or `partial`.
   - The card `kind` comes from the override `concept_type`, else from the model's enum value, else `other`.
   - `summary` is required in the stored card.
9. **Regions:** a region is stored when it validates and is used by nothing. T-010 builds no region probe.
