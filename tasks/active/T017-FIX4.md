## Fix

- `config.py` `validate_anthropic_writer_schema(schema, source)` (new): runs `anthropic_output_schema` on a resolved writer schema and refuses with `"<source>: cannot be sent to Anthropic structured output: <path and reason>"`; `writer_provider(config)` (new) returns the writer backend's provider or None for a sentinel.
- `writer.py:147-157` `prepare_write`: a non-local writer is refused only when the provider is not Anthropic (Gemini keeps `cloud structured output mapping is not verified`); on Anthropic the resolved schema (`registry.get(...)`, the bundle's or a contract's) goes through the check, `source` is `output_schema.json` for the bundle schema, else `schema <id>`. Local bytes unchanged (the branch is not taken).
- `profiles.py` `_view` (shared by `profile check` and `profile resolve`): after `load_output_schema`, an Anthropic writer checks the bundle schema and raises `ProfileError('PROFILE_OUTPUT_SCHEMA_INVALID', ...)` naming `output_schema.json`, before any golden case runs. `profile register` writes the manifest and reads no `output_schema.json`, so it has no bundle schema to check (not changed).
- Probe: no code change (Q1); `test_the_start_probe_posts_the_bundle_schema_not_a_registered_one` and `test_a_bundle_schema_the_backend_refuses_stops_the_writer_before_any_real_request` pin that the one compile-limit request carries the stripped bundle schema and that an HTTP 400 stops the writer before any real request, with the `output.transport` hint.
- `profiles.py` `check_profile`: `entry['error_message']` = the text of a `ConfigurationError`, cut to `GOLDEN_ERROR_MESSAGE_CHARS` (1000); the field is additive in `golden_results.json`, described in `contracts/README.md` (no schema file exists, no GUARDED file touched).
- R-004: nothing rewrites the system prompt or the schema; `prepare_write` returns `system` unchanged (asserted `b'Admin\r\n'`), the request test asserts `system == 'ADMIN'` first.

## Configuration impact

No new key and no new default. The writer's provider and format come from `vlm.roles.writer` and `vlm.backends.<name>.provider` (validated at load); the schema from the admin bundle (`output_schema.json`, `output_schema_id`). One new literal: `GOLDEN_ERROR_MESSAGE_CHARS = 1000`.
