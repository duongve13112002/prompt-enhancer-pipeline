## Moved from LESSONS_LEARNED 2026-11-16 12:5x (budget)

- 2026-11-15, a Gemini implementation job failed at launch (`.tmp\agy-jobs` missing). The PM first logged `purge_tmp.py` as the root cause without evidence that the folder had ever existed here; that was wrong.
  - **Verified root cause:** the machine's single scheduled task `AgyRunner` passes `-ProjectRoot` for another project on this machine (last run 2026-11-06). `scripts/agy-runner/setup.ps1` was never run for this project, so `.tmp\agy-jobs` never existed here. Earlier Antigravity use here was read-only `gemini-review.ps1` jobs under the user's account, and those still work; the write path was used here for the first time today.
  - **Two traps in `setup.ps1`:**
    - `Set-RunnerAce` counts an existing Deny rule for the runner account as "already set", so a rerun grants nothing.
    - `setup.ps1` re-registers the one task with `-Force`, so running it here would unbind the other project.
  - **Prevention:** log a root cause only after the failing object is shown to have existed (creation time, owner or a log line). `gemini-launch.ps1` refuses when the task's `-ProjectRoot` is not this root; `setup_project.py check` reports the runner binding; `Set-RunnerAce` matches the rule type (fixes in progress, S42). The purge protections for the runner folders stay as hardening.
  - **Evidence:** `Get-ScheduledTask AgyRunner` arguments and `Get-ScheduledTaskInfo` LastRunTime 2026-11-06 18:42; `.tmp/agy-rca/report.md`.
