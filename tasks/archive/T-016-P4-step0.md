### Verified facts the design rests on (source-verified unless marked)

1. **S0 pins the current snapshot, never a named one** (`intake.py:191-211`: `KnowledgeGateway.pin()` -> `store.pin()` reads CURRENT). So "an explicitly named published snapshot" can only mean: the named id must equal the current published id at run start and at the end of each scenario (a mid-run publish or rollback is a refusal, not a silent mix). The library cannot pin an older snapshot, and I will not change T-015.
2. **`eval_scenarios` cannot hold the draft** (`eval_scenario.v0` has `additionalProperties: false`; no `draft_*` field). The draft's five columns are `draft_link_details`, `draft_edit_key`, `draft_rag_enabled`, `draft_language`, `draft_format` (read from the Parquet schema). So `eval run` reads the named Parquet directly through an adapter and writes **no** `eval_scenarios` or `eval_labels` row (those belong to `eval build`, T-003).
3. **`eval_results` columns** are `run_id, scenario_id, metrics (JSON), status (response_envelope status enum), config_hash` (`tables.py:128-130`); key `(run_id, scenario_id)`. Set, snapshot, trace, variant and scorer provenance therefore go inside `metrics`, with no new column. `DataStore.append` writes one segment file per call by temporary file and rename (`store.py:1392-1398`, `_anchored.py:94-106`), so a segment is whole or absent; `read` loads **every** segment and refuses a repeated key (`:1400-1412`), so a duplicate must be prevented before `append`, not discovered on read.
4. **Retrieval-off structure** (`pipeline.py:121-128`, `:144-150`; `intake.py:143`, `:192`): `rag.enabled` is fixed per `Pipeline`; the request-set read keys drop `candidates/embedding/assembly` when off (`config.py:704-709`). `open_knowledge_store(..., 'eval run')` already refuses when `rag.enabled` is false (`store.py:266`). So an off record runs in a `Pipeline` built from a copy of the profile with `rag.enabled: false`, in its own `async with`, and the runner opens no store for it.
5. **Edit source bytes** are readable by content id from the pinned snapshot only (`PinnedSnapshot.read_image`, `store.py:706-709`, retained originals, KBS-F3), through a store the **runner** opens for the on variant. No such path exists for an off variant (R-009: no KB access): see Q2.
6. `COMMAND_READS['eval run']` (`config.py:89-92`) reads the whole `evaluation` block, whose base example holds `min_items_per_class: design_required`, so today `eval run` would refuse on a sentinel the runner never uses. The runner consumes `evaluation.scenario_kinds` and `evaluation.split_by` only (a record kind must be configured; a concept must not sit in both splits). `languages` is documented as "an example list, not a limit" and is not validated against.
7. The envelope `output` may be a string, object, array or null (`response_envelope.v0`), the status enum is `success, repaired, degraded, needs_clarification, failed`. The S2 link list is in the trace row (`body.plan`, `envelope.py:82-83`); how to read one row by `trace_id` without loading all traces is **not yet read** (`trace_store.py`): phase 1 reads it; the link check stays `not_run` ("trace row unavailable") if no bounded read exists.
8. Code identity in this repo is a **declared revision constant**, never a source hash (`tests/test_stage_revisions.py:1-6`); the pipeline's own is `GoldenAdapter.identity = 's0-s6.v1'` (`pipeline.py:312`).

### Unknowns and ranked questions (each with my proposed answer; none blocks the non-dependent phase 1)

1. **Variants: what does "retrieval on and off" run per scenario?** Proposal: a required argument `--variants record|both`, no default. `record` runs each scenario once, in the variant its record states (`draft_rag_enabled`). `both` adds the off variant to every on record (so the judge pack can compare two blinded outputs of one scenario); an off record always runs off only (running a "retrieval off" kind with retrieval on contradicts its key). Result unit is (scenario, variant): `run_id = <identity16>-<variant>` so the key `(run_id, scenario_id)` stays unique and "one durable result per scenario" holds per variant. PM decision pending user review: a pair per scenario doubles the model calls, so `both` is the user's explicit choice per run.
2. **Edit scenario in the off variant has no source bytes** (R-009 forbids the store). Proposal: an optional `--source-images <dir>` (inside the project root, no link on the path, files named by the image-id digest hex, each file's SHA-256 must equal its image id). It is required only when a run contains an off edit; otherwise a missing file refuses the whole set before the first call. The on variant always reads from the snapshot, never from this directory or the knowledge-base tree. The draft has no off edit record (all five `rag_off` records are `generate`), so the real draft needs no such directory.
3. **Where do the summary, judge pack and import records live?** Proposal: results in `eval_results` (one segment per result, existing table); everything else in an explicit sidecar tree `<data_root>/eval/runs/<run_id>/` written only through the anchored atomic writer (`_anchored.atomic_write_bytes`, no raw write; the scanner test `test_storage_anchored_writes.py` guards that). It needs two small `DataStore` additions: `write_sidecar` / `read_sidecar` (path rule of `DataStore`, under `eval/runs/` only) and `iter_rows(name)` that reads segment by segment so resume never holds every result (R-017). No new table column.
4. **How is a failed attempt counted, and is it retried?** Proposal: an operational failure (exception, no envelope) writes **no** `eval_results` row; it is counted `failed` in the summary and logged in `attempts.jsonl` (error class only, no payload), and **is retried on resume** (it was never a successful call). An honest `failed`/`degraded` envelope is a **completed** result with that status (R-024), never `failed` in the runner's count. `skipped` = not selected by an explicit `--split` filter or an off-only rule (reason recorded); `not_run` = selected but not attempted (interrupt, or a variant that needs an unavailable input).
5. **Structural link check alignment.** Proposal: align the planner's mention to the key's mention by **exact string equality** (no normalisation, no list); a key link whose mention is not found is `unaligned`, counted separately from pass and fail; family and negation parts (`draft_link_details`) stay semantic and `not_run` until scored. PM decision pending user review.

Not asked, decided conservatively and marked "PM decision pending user review": **disagreement** = any difference between the two scorers on one rating (no threshold, so no invented value); the rubric dimensions are the Q1 list (constraint survival per constraint id, leakage, under-editing, link alignment, family/conflict, negation), each applicable only where the key states it.

### Design

**Commands.**
`eval run --config C [--overlay O] [--project-root R] --set <parquet> --snapshot <id> --variants record|both [--split fit|test|all] [--source-images <dir>] [--resume]`: `--set`, `--snapshot` (required iff any run is on; refused if every run is off, so an off-only run touches no knowledge base), `--variants` and `--split` are required, never defaulted. All paths are resolved under the project root with no link on the path (as `refuse_linked_configuration`).
`eval import --config C [--overlay O] [--project-root R] --run-id <id> --scores <file> --scores <file> ...`: at least `evaluation.judge.min_scorers` files; all files are validated before one byte is written (all or nothing).
`eval build`, `eval fit`: unchanged refusals (exit 2). Exit codes as the other commands: 0 done, 1 operational failure, 2 refusal before any side effect. `--resume` is not needed for identity resume (below) but a run directory that exists with another manifest is refused; the flag is dropped from the final syntax unless the PM wants an explicit consent to continue (default proposal: no flag, resume is automatic only when the identity is identical).

**Draft adapter** (`eval_set.py`, new). Reads the Parquet by record batches (`ParquetFile.iter_batches`, bounded by `evaluation.run.max_set_bytes` on the file size, SHA-256 streamed in chunks), validates each record against `eval_scenario.v0` (through the project `Catalog`) after removing exactly the five `draft_*` keys, and validates each `draft_*` field by type (`draft_rag_enabled` bool, `draft_edit_key` null or a JSON object string with `targets/delta/preserve` string lists, `draft_link_details` list of closed objects, `draft_language`, `draft_format` strings). Unknown extra columns refuse. Every string is carried byte for byte (no `str.strip`, no normalisation, no re-encode). Pass 1 validates all records and every referenced id (kind in `evaluation.scenario_kinds`; a concept in both splits refused per `split_by: concept`; each `concept_id`, `family_member_ids`, `family_conflict_ids` and edit `source_image.image_id` must exist in the named snapshot's `concepts` / `images` tables; duplicate `scenario_id` refused). Pass 2 runs. Only ids and counts are held between passes, never the records.

**Run identity (resume key).** `identity = sha256(canonical JSON of {set_sha256, snapshot_id, manifest_sha256 (None when all off), effective config hash of each variant (covers every vlm role, backend and model id), configured writer/verifier model ids, EVAL_RUN_REVISION, pipeline identity 's0-s6.v1', variants, split, source_images listing hash, evaluation.judge.blinding_seed})`; `EVAL_RUN_REVISION = 'eval-run-1'` is a declared artifact-bound constant (stage-revision convention). `manifest.json` (immutable) holds these inputs and is written first; a rerun with the same identity continues, any change makes a different `run_id` (never an overwrite). Resume: stream `iter_rows('eval_results')` for the run id into a set of finished `scenario_id`, then run only the missing ones; before each `append` the runner re-checks the finished set, so no second row for a key is ever written. The model identity actually served is reported in the trace `calls`; its live check is T-017.

**Per scenario** (one `async with Pipeline` per variant for the whole run, entered lazily, closed in `finally`; one scenario at a time, in file order): build the `request.v0` request (prompt as stored; edit: source bytes from the snapshot by content id, or from `--source-images` for an off edit, base64), `await pipeline.enhance(request)`, build `metrics`, `append` the row, then `await response.after_delivery()` (nothing is delivered to a user; the acknowledgement only lets the lifecycle finish the trace), then discard. The on variant also re-reads the current snapshot id after the call; a change aborts the run as an operational failure (the result is not written).

**`metrics` layout** (validated by a closed in-code schema before append; no table column added): `{"evidence": "structural", "variant": "on|off", "disposition": "completed", "set_sha256", "snapshot_id", "scenario_kind", "split", "trace_id", "envelope": {"status", "schema_valid": true, "retrieval_state"}, "literal": [{"constraint_id", "present": bool}] , "links": [{"mention", "alignment": "aligned|unaligned", "concept_id_match": bool|null}], "semantic": {"state": "not_run", "reason": "scoring contract not approved"}, "intervals": {"state": "not_run", "reason": "interval method not approved"}}`. `status` column = the envelope status; `config_hash` = the effective config hash. Literal check: for each key constraint of type `literal_text` whose `span` is non-empty, `span in output` byte-exact, defined only when `output` is a string, else `present: null` with reason `output_not_text`.

**Summary** (`summary.json`, recomputed from the durable rows and `attempts.jsonl` at every end, interrupt included, then replaced atomically; never trusted as input): `{"run_id", "selected": N, "completed": c, "failed": f, "skipped": s, "not_run": n, "denominators": {"c + f + s + n == selected"}, "envelope_status_counts", "structural": {"literal": {"checked": k, "present": p, "unchecked": u}, "links": {...same...}}, "semantic": {"state": "not_run"|"agent_judged", ...}, "intervals": {"state": "not_run", "reason": ...}}`. Every ratio names its denominator; a failed, skipped or `not_run` scenario is in no pass count.

**Judge pack** (`judge-pack.jsonl` + `judge-pack.header.json`, written once per run after the run completes, from `eval_results` rows; closed schema `contracts/schemas/eval_judge_pack.v0.schema.json`). Header: `schema`, `pack_id` (sha256 of the item lines), `rubric` (text of `prompts/<evaluation.judge.rubric_prompt_id>` verbatim and its hash), `scale {min,max}`. One line per scenario: `scenario_id`, `kind`, `task`, `prompt`, `key` (expected links, constraints, `draft_edit_key`, `draft_link_details`: the answer key, sent by decision 154), `dimensions` (derived from key structure: survival per constraint id; `link_alignment` if links; `family_conflict` if a family link; `negation` if a negated link or a `negation` constraint; `leakage` and `under_editing` for edit), `outputs`: list of `{label, output}` in a seeded order (`label` is `A`, `B`, ...). **Nothing else about the output**: no envelope status, warnings, retrieval state, attachments, trace ids, variant. File names carry no variant. The order of each scenario is a permutation drawn from `random.Random(f"{blinding_seed}:{scenario_id}")` (a stable text seed), and `judge-key.json` (never sent) maps `(scenario_id, label)` -> variant and trace id. Pack construction streams rows; one line at a time.

**Score file** (closed schema `eval_judge_scores.v0.schema.json`, JSON, at most `evaluation.judge.max_score_file_bytes`): `{"schema": "eval_judge_scores.v0", "pack_id", "scorer": {"id", "family", "model"}, "scores": [{"scenario_id", "ratings": [{"label", "dimension", "ref" (constraint id or null), "value"}]}]}`; `additionalProperties: false` everywhere; **no free-text field** (agent text is data, R-026; none is stored). `value` is an integer in `[score_min, score_max]`.

**Import** validates, for every file: schema; `pack_id` equals the run's pack; scenario ids are a **subset-free exact cover** of the pack (every scenario once: unknown, duplicate, missing refused); every `(label, dimension, ref)` is one the pack's `dimensions` lists, exactly once; ints in range (bool refused); scorer `family` not in `evaluation.judge.under_test_families`; the files' families are pairwise different and the count is at least `min_scorers`; scorer ids distinct. Then, with the key, it unblinds and writes `imports/<import_id>.json` (one atomic file): per scorer and variant and dimension the count and mean, `disagreements` (every `(scenario_id, variant, dimension, ref)` whose two values differ, with both values), `evidence: "agent_judged"` on every value, the scorer descriptors. It writes **no** `eval_results` row and nothing under a fit path; `summary.json` is recomputed with `semantic.state: "agent_judged"` and the pilot-only note, while thresholds, calibration, `eval fit` input and every interval stay `not_run`. The stdout JSON lists the disagreement count and the user-review flag.

**New profile keys** (optional in `enhancer_config.v0.schema.json` per decision D8; required and validated by `validate_evaluation_run` / `validate_evaluation_judge`; base example `deploy_required` or `design_required`, dev example a concrete dev-only value, each with an override test and a refusal test):
`evaluation.run.max_set_bytes` (int >= 1), `evaluation.judge.blinding_seed` (int >= 0), `evaluation.judge.score_min` / `score_max` (ints, min < max), `evaluation.judge.min_scorers` (int >= 2), `evaluation.judge.under_test_families` (non-empty list of non-empty strings; a **declared identifier list**, compared by exact equality: a family cannot be derived from a model name without a word list, R-015), `evaluation.judge.rubric_prompt_id` (string, resolved like `vlm.roles.*.prompt_id`), `evaluation.judge.max_score_file_bytes` (int >= 1). `COMMAND_READS['eval run']` is narrowed to the consumed leaves (`evaluation.scenario_kinds`, `evaluation.split_by`, `evaluation.run`, `evaluation.judge.blinding_seed`, `evaluation.judge.rubric_prompt_id`, `evaluation.judge.score_min`, `evaluation.judge.score_max`) and `eval import` gets its own entry; `REQUEST_COMMANDS` and `RAG_COMMANDS` stay as they are (`eval run` is in both already).

**Retained literals (classification).** `EVAL_RUN_REVISION` (artifact-bound), the table names and sidecar layout (artifact-bound), `A`/`B` label alphabet (protocol-bound), the five `draft_*` names (artifact-bound: the T-003 draft layout), `agent_judged` and the status words (protocol-bound), exit codes 0/1/2 (protocol-bound). No `defect`.

### Pre-mortem (decision 169): classes and the test that rules each out

| # | Failure class | Test (all through the real module entry point unless stated) |
|---|---|---|
| 1 | resume re-calls a scenario that succeeded, or writes a second result | kill the run after k results (a double that raises on call k+1); rerun; assert each scenario's model-call count == 1 over both runs and exactly one row per `(run_id, scenario_id)` |
| 2 | an interrupted write leaves a half result that counts as done | fault inside `append` (unit, labelled): no segment, scenario still missing on resume; a stray `.`-prefixed temp file is ignored; a truncated segment is refused, not counted |
| 3 | summary counts failed/skipped/`not_run` as passed, or wrong denominator | set with one failing double call, one skipped split, one unattempted; assert `c+f+s+n == selected` and pass counts exclude all three; property: the identity holds for any mix |
| 4 | a semantic metric shows a value without imported scores | summary before import has `semantic.state == "not_run"` with the reason; no number; after one score file refused, still `not_run` |
| 5 | foreign snapshot, missing source image, invalid split, scorer of the family under test accepted | one test each (named id != current; edit id absent from snapshot; concept in both splits; scorer family in `under_test_families`; two scorers of one family); each refused with exit 2, no model call, no file |
| 6 | the pack reveals the variant (order, ids, field names, file names, trace ids, warnings) | scan the pack and its file names for the variant words, trace ids and warnings of the run; property: for any seed the label permutation is a bijection and a fixed-order mutant is caught by a statistical-free exact test (the same seed repeats, two seeds differ on at least one of many scenarios) |
| 7 | import accepts extra fields, a missing/duplicate/unknown scenario, an out-of-range value, a wrong pack | Hypothesis-mutated valid score files: every accepted file equals the model; every other file is refused with no side effect |
| 8 | `agent_judged` scores reach a threshold, calibration or fit path | import writes no `eval_results` row; `eval fit` still refuses; a grep test that no reader of `eval_results` metrics accepts `evidence != "structural"` |
| 9 | a retrieval-off record opens the store | off-only run with the store directory absent and `open_knowledge_store` replaced by a raiser in the child (labelled hook); `--snapshot` with an all-off set refused |
| 10 | multilingual text normalised or re-encoded | Hypothesis Unicode and nested JSON prompts survive the adapter, the request, the pack and the result byte for byte (the double receives the exact prompt) |
| 11 | the whole set or every result held in memory | the adapter yields one record at a time (unit, instrumented generator); `iter_rows` reads one segment per step (unit, counted reads) |
| 12 | a path or separator works only on Windows | paths built by `Path`; the draft has `\` free ids; CI both-OS is PM-owned (`not_run` here) |
| 13 | a set or score file escapes the project root through a link | link on `--set`, `--scores`, `--source-images` (junction/symlink where creatable) refused |
| 14 | a mid-run publish changes the snapshot | the double publishes between calls; run stops, result not written |
