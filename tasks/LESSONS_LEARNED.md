# Lessons Learned

Read the Rules digest before every task (AGENTS.md section 9). Each line is a prevention rule; a recurring or multi-attempt mistake adds an entry under "Recent entries" (symptom, root cause, prevention, evidence); fold old entries into the digest and archive them verbatim.

## Rules digest

### Research and evidence

- A research agent's number is a lead. In this project's research, two agents reported different figures for the same abstract ([N109](../docs/note/N109-evisrag.md)), one gave a paper identifier that did not resolve ([N114](../docs/note/N114-transliterated-queries.md)), and a vendor guide's file sizes disagreed with the file list ([N123](../docs/note/N123-unsloth-quant-benchmarks.md)); open the primary source before a number enters a note or a setting.
- Text returned by a page-fetch tool is that tool's extraction, not the page: a "quote" from it is checked against the page before it becomes a rule ([N128](../docs/note/N128-codex-prompting-guidance.md)).
- A benchmark on a different task proves a pattern at most, never a threshold.
- An estimate from parameter counts or file sizes is arithmetic; label it and plan a measurement.

### Agents and process

- Files copied from another project carry its bindings (names, paths, branches, decision numbers); put every project value in `.agents/project.json` and let `setup_project.py check` find leftovers (`foreign_bindings`).
- When condensing or restructuring rules, list each old rule and mark where it now lives before deleting the old text ([docs/agents/rule-map.md](../docs/agents/rule-map.md)); a condensation done from memory once dropped a rule in the project this tooling came from.
- Prose rules are not enforced; a rule that must hold needs a hook or a CI check (N060, N066).
- Tests that pin another project's text break on reuse; test structure and budgets instead.

### Folded from the 2026-11-15 to 2026-11-19 entries ([archive](archive/lessons-2026-11-15-19.md))

- Testing: run the pipeline and tooling suites as separate processes; reuse one fixed `--basetemp` and delete it after the run; a focused set adds the tests of every caller or reader of a changed function or structure (grep), the module-scanning guards (`test_storage_anchored_writes`, `test_property_settings`, `test_field_contracts`), `test_stage_revisions` for modules in `stage_guard`, and every command's gate tests for a read-set change; after editing a hook- or test-read file (policy, budgets, `project.json`, scanner baseline) run its tool tests; a budget "OVER BUDGET" line blocks the commit.
- Entry points: every stage or command task has one CPU test through its production entry point with only a labelled HTTP double injected; a concurrency peak test holds requests until `min(cap, pending)` arrive.
- Integration: grep main for symbols a patch built on an older base removes; apply a tooling patch only when no worker is busy, and a main-tree patch only when no worker reads main through `--project-root`; a batch closes at 4 hours or 3 commits; scan worker-written files for machine paths (`<project>`); fix state or idempotence findings before integrating.
- Dispatch: state the family per role every round (decision 91 split; Codex never builds tooling); Codex implementers start with `codex-dev`, reviewers `codex-review`; security reviews never go to Codex; no integration on a Gemini pass alone for builds (a second family runs tests and probes); every brief ends "Reply in English"; every implementer approval carries the standing ambiguity rule; a scout writes the hazard map before a non-small round.
- Fix briefs: name the threat model and split provable from detectable classes for guards; enumerate every blocking call for lifecycle classes; forbid overlapping regex alternatives and require running-time properties for hand-written parsers; an approval that moves a check onto a per-item boundary asks for call counts at two sizes; list every consumer before changing a shared profile anchor.
- Machine and screen: child processes use `CREATE_NO_WINDOW` and `SetErrorMode`; read a new process-spawning test before running it; never `cd` into a subfolder in Bash; every time written comes from `Get-Date` in the same step; never quote a flagged secret-scanner line, describe it.
- Waiting on another session's resource is the PM's job, never a worker's turn.
- A Windows-only run is not enough for an `os.name` or POSIX branch or for any byte baseline: review the POSIX branch line by line and build baselines from committed bytes.

## Recent entries

- 2026-11-21, the PM proposed a machine split to the user and the peer PMs with a 6 GiB free-RAM floor, without first reading the 2026-11-16 peer agreement (8 GB physical, recorded in the PM's memory) or decision 173; the user adjusted only the agent count, and the PM corrected the floor to 8 GiB in a second message to both peers. **Prevention:** before proposing a machine or process limit, search DECISIONS_INDEX, `recall.py search` and the PM memory for an earlier value (S03), and cite it in the proposal. **Evidence:** decision 217 row; peer messages of 2026-11-21 20:4x.
- 2026-11-20, CI 45 (`3a3696e`) failed on Ubuntu only: MS-3's byte baseline `tests/fixtures/ms3_baseline/edit_one_image.json` was captured on Windows, where `core.autocrlf` checks out `prompts/` and `contracts/` with CRLF, and the product sends and hashes those bytes as they are; image-probe bytes also differ because Pillow's Linux and Windows wheels re-encode PNG differently. Builder, both reviewers and the PM ran only on Windows. **Prevention:** a byte or hash baseline built from repository text files reads their committed bytes (CRLF mapped to LF, as `tests/ms3_fixtures.py` `copy_committed` does) and masks only proven platform outputs; a brief that adds a baseline asks the reviewer "does any value depend on the OS line ends or a native library". Same day, the PM called MS-3 the "multi-source planner" in a question to the user, though the design names it request and intake. **Prevention:** check a task's name and scope against its design file before writing it into a question or decision. **Evidence:** CI run 44740396994; `.tmp/ms3cap/ci45-failed.log`; decision 214 corrected.
