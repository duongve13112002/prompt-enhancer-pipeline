# Agent workflow tools (PM tooling, not product code)

> Decision numbers above 100 in this file (for example 232, 353, 503) name decisions of the sibling project the tooling came from; they are history only. This repository's decisions: [tasks/DECISIONS_INDEX.md](../../tasks/DECISIONS_INDEX.md). Policy that applies here: [PM_POLICY](../../.agents/policy/PM_POLICY.md).

Launcher, guard hooks and measurement scripts for Claude Code CLI workers (decisions 232, 249). The guard ideas were
reimplemented from the evaluation in `.tmp/ecc-research/report.md`; no external code was copied and the external package is not installed.
How to run Claude CLI sessions as subagents, check prompt caching and usage, and run Gemini jobs: [CLAUDE_CLI_SUBAGENTS.md](CLAUDE_CLI_SUBAGENTS.md).
Overview for new developers and agents: [docs/agents/README.md](../../docs/agents/README.md). Codex jobs: [CODEX_JOBS.md](CODEX_JOBS.md). Hook template: [settings.example.json](settings.example.json).
Orchestration rules (DELEGATE mode, registry, reuse, limits): [.agents/ORCHESTRATION.md](../../.agents/ORCHESTRATION.md).
Policy lives in [.agents/policy/PM_POLICY.md](../../.agents/policy/PM_POLICY.md); brief rules in [.agents/policy/AGENT_BRIEF_FOOTER.md](../../.agents/policy/AGENT_BRIEF_FOOTER.md).

All scripts derive the project root from their own location (`tools/agent-workflow/` is two levels below it) and keep runtime state
under `<root>/.tmp/` (`pm-state/`, `cli-jobs/`, `agy-work/`). Run them from the canonical checkout: a worktree copy would use the worktree's own `.tmp`
(and has no `.venv`). Nothing here reads or writes `~/.claude` settings or `.secrets/`.

## Starting workers

```text
python -B tools/agent-workflow/cli_worker.py start --name w1 --profile dev-small --model sonnet --effort high \
    --cwd <worktree> --message-file <brief> --label "TASK a1"      # run with the shell tool's background mode
python -B tools/agent-workflow/cli_worker.py send --name w1 --message-file <msg> [--effort xhigh] [--pid-checked]
python -B tools/agent-workflow/cli_worker.py status [--all] [--json]
python -B tools/agent-workflow/cli_worker.py retire --name w1 [--force]
```

**Worker profiles (decision 379, the normal path).** `start --profile <role>` takes the auto-compact window, context-nudge thresholds and cache TTL from [worker_profiles.json](worker_profiles.json); any explicit `--autocompact-window`, `--ctx-nudge` or `--cache-ttl` overrides the profile value (`--model` and `--effort` stay required flags unless a role sets them). The loader refuses an unknown role, a missing field, an unknown key, an invalid value and a nudge not below the window (role and field named). An override must keep that rule: `--profile dev-large --autocompact-window 350000` is refused unless `--ctx-nudge` drops below 350000 too. `status` shows `profile=<role>`; the registry stores `profile` (`null` without one). Without `--profile` the flag defaults below apply unchanged.

| Role | `autocompact_window` | `ctx_nudge` | `cache_ttl` |
|---|---|---|---|
| `dev-large` | 400000 | 300000,360000 | 1h |
| `dev-medium` | 300000 | 220000,270000 | 1h |
| `dev-small` | 200000 | 150000,180000 | 1h |
| `review` | 250000 | 180000 | 1h |
| `spike` | 300000 | 220000 | 1h |
| `scout` | 150000 | 120000 | 5m |
| `helper` | 150000 | 120000 | 5m |

| `start` flag | Default | Effect |
|---|---|---|
| `--profile ROLE` | none | Role from `worker_profiles.json` supplying window, nudge and TTL (and optionally model and effort); explicit flags override |
| `--cache-ttl 5m\|1h` | profile value; required without `--profile` | `1h` for multi-turn chains or long tool runs; `5m` for one-shot jobs |
| `--process-guard on\|off` | `on` | Hook A |
| `--tool-guard on\|off` | `on` | Hooks E and F; `off` falls back to the prefix git deny rules (`LEGACY_GIT_DENIES`, not a boundary) |
| `--git-guard readonly\|merge` | `readonly` | `merge`: also `git merge --no-commit --no-ff` (or `--squash`, `--abort`) and `git add` inside `--cwd`, which must be a worktree under `git_guard.worktrees_dir`; needs `--tool-guard on` |
| `--task-file F` | none | Hook G writes its block into F (an existing `.md` inside the root) |
| `--ctx-nudge T1,T2\|off` | profile value, else `170000` | Hook B thresholds (strictly ascending token counts); the last one must stay below the window |
| `--autocompact-window N\|off` | profile value, else `230000` | Auto-compact window of this worker only (100000-1000000), passed as `CLAUDE_CODE_AUTO_COMPACT_WINDOW` in the child environment; `off` leaves Claude Code's own window. See [Context policy](#context-policy) |
| `--loop-warning N` | `5` | Hook D window; `0` disables |
| `--advisor off\|opus\|fable\|sonnet` | `off` | adds `claude --advisor <model>` (decision 266 pilot). Advisor calls read the whole transcript uncached and are billed under the advisor model; the turn's per-model tokens and cost are stored as `last_model_usage` in the registry |
| `--mcp default\|minimal` | `default` | `minimal` adds `--strict-mcp-config` with an empty server list (no MCP tools or instructions; see Evaluation) |

`status` hides retired workers (a note counts them); `--all` lists them and `--json` prints machine-readable rows. A `busy` row reads the tail of the live log (`LOG_TAIL_BYTES`, bounded) for `ctx=`, the log name and its age, and shows whether the launcher process (`launcher=`) and the `claude` child (`worker=`, recorded as `worker_pid` right after it starts) are alive. `send` is refused while either recorded process lives, even when the launcher was killed without its tree; only when both are gone (crash, closed terminal) does it print a WARNING and resume the session. **A PID alone is never trusted (PID reuse, decision 503):** the creation time of each process is recorded beside its PID (`launcher_created`, `worker_created`; Windows `GetProcessTimes`, Linux `/proc/<pid>/stat` field 22 plus `btime`), and a process counts as the worker's only if it exists with that creation time (within `PROCESS_TIME_TOLERANCE_SECONDS`, 2 s, a safety-bound constant). After a reboot an unrelated process that got the old PID therefore shows as `DEAD`, does not block `send`/`start`/`retire`, and is never killed (`kill_tree` needs the recorded time; `run_turn` otherwise stops only its own `Popen` child). Entries written before this change have no creation time and are judged against their turn start (`last_used`): a launcher process created after it is not ours; a worker process created before it is not ours; anything else, or an unreadable time, is `unknown` (`launcher=unknown`, `launcher_state` in `--json`): `send` and `start` refuse with one line, and the PM, after checking the PID (`Get-Process -Id <pid>` / `ps -p <pid>`), runs `send --pid-checked` or `retire --name <w> --force`. The registry lock file holds `<pid> <token> <creation time>` and counts as held only while that process (PID and creation time) lives; a legacy lock without a time and with a running PID is held only if the file was written after the system booted (boot time unknown: held). `hooks/pm_invariants.py` judges a launcher through `cli_worker.entry_process_state` (loaded from the sibling file, not duplicated), so a reused PID no longer hides a dead launcher. `retire` is refused while the launcher or the worker process lives (stop its tree by PID first); a `busy` entry that recorded no PID cannot be judged and needs `--force` once nothing runs; `start` refuses to reuse a retired name while a process of the old worker lives; a finishing turn writes its result only if the registry entry still has its session id. A launcher that dies on an exception marks the worker `error <ExcType>` instead of leaving it `busy`; a worker name started again after `retire` continues the log numbering, so older logs are never overwritten. The registry is written atomically (temp file plus retried `os.replace`) and the lock file holds its owner's PID: a lock of a live owner is never broken, one of a dead owner is broken at once, one without a readable owner is broken after 30 s (a lock created between the check and the move is put back, and a holder removes only its own lock). Stream logs are split on LF only and lines that are not JSON objects, or have non-numeric usage, are skipped.

Flags are stored in the registry entry (`.tmp/pm-state/cli-workers.json`) and apply to every turn of that worker; `send` never changes them (a changed window can change the cache prefix). The `cwd` must be inside the root.
Developers who want a hand-run worker use the same commands; the registry, logs (`.tmp/cli-jobs/<name>/NNN.jsonl`) and results (`NNN.result.md`) are shared with the PM.
Run tests through the limiter: `python -B tools/agent-workflow/test_slot.py -- <interpreter> -m pytest ...` (footer rule 10).

## Codex workers

`cli_worker.py start --backend codex` runs a Codex CLI session as a worker with the same commands, registry, logs, task file, brief lint, footer, timeout, stop and supervisor events as a Claude worker. Roles cover code and tests, review, live-web research and documents. Code: [codex_backend.py](codex_backend.py) (config, command, startup check, log parsing, purge), [usage_snapshot.py](usage_snapshot.py). Tests: `tests/test_cli_worker_codex.py` with the labelled test double `tests/fake_codex.py` (live Codex runs are not part of the suite).

**Setup (Windows).**

1. Install Codex CLI and note the absolute path of the **native** `codex.exe` (not the `.cmd` shim: it breaks `-c` quoting; a shim is refused).
2. Copy [codex_profiles.json](codex_profiles.json) to a local file under `.tmp/` and replace every `<placeholder>` (command, model ids). The tracked file keeps placeholders on purpose; the loader refuses them, so nothing machine-specific is committed.
3. Use the canonical project venv: required `runtime.venv_dir` is project-relative (`.venv` in the example), never null or inferred. The launcher uses its platform scripts directory on PATH and its interpreter for the startup reader: `Scripts/python.exe` on Windows, `bin/python` on POSIX. `PYTHONPATH` stays the worker cwd's `src`; `PYTHONNOUSERSITE=1` and `PYTHONDONTWRITEBYTECODE=1` stay enabled. Workers must not use `-I` when importing their worktree source; the isolated startup reader only reads files.
   **Windows host setup is user-owned, never performed by an agent.** The venv launcher needs to read its base Python installation, including the standard-library and DLLs. The user grants **read and execute only**, `(OI)(CI)RX`, on that base Python folder to both `CodexSandboxOffline` and `CodexSandboxOnline`. `(OI)(CI)` inherits the read/execute grant to files and subdirectories; do not grant write/modify or widen access to private project files. A reader startup failure names this prerequisite. PM measured canonical venv startup/imports under Codex 0.167.0 with `elevated`; that is machine-specific PM evidence, not a suite/live claim here.
   Both configured and canonical `.venv` must remain outside every writable cwd and extra grant after resolving links, including ancestors and descendants. Project-root cwd therefore refuses: use a separate worktree. Every current role extends writable `:workspace`; a role named read-only does not make root cwd safe. Deny metadata is checked at admission and profile emission even with `extra_write_paths=[]`.
   **A sandboxed job never starts a detached child**, including `DETACHED_PROCESS` or PowerShell `Start-Process`: on this machine it fails with `0xc0000142` and shows a popup on the user's screen. Run child commands in the foreground and wait for them. Host-only orchestration is outside this job rule.
   Existing `.tmp/pm-state/codex.local*.json` files need `usage.session_file_limit` (for example `8`) and required `runtime.extra_write_paths`; use `[".tmp/pm-state/test-slots"]` to allow the shared test limiter to write its locks. The PM updates those local files. Retire and restart workers whose stored resolved configuration predates required keys. Migrate local profiles from `runtime.python_dir` to required `runtime.venv_dir`; old registry rows require retire and restart and are never silently migrated.
4. `python -B tools/agent-workflow/cli_worker.py start --backend codex --profile codex-dev --codex-config <local copy> --name c1 --cwd <worktree> --message-file <brief>`.

**Configuration** (every value validated, a missing or invalid one refused, no model id in source). `runtime`: `codex_command` (**one executable path, a string**: a list, a command line with flags, a `-`-leading word or a `.cmd`/`.bat`/`.ps1` shim is refused, so no flag can ride in on the prefix; all flags come from the launcher's grammar), `codex_home` (optional; absent means `CODEX_HOME` if set, else `~/.codex`; exported to the child only when configured; no containment check, because Codex keeps its login there), `windows_sandbox` (`elevated`, `unelevated` or `null`; restricted reads need `elevated`), `permission_profile`, `extra_deny_paths`, `extra_write_paths` (required list of root-relative write grants; tracked `[]`), `scratch_dir`, `venv_dir` (required project-relative venv), `check_timeout_seconds`, `env_allow`. `roles.<name>`: `model` (one word, never `-`-leading), `effort`, `web_search` (`disabled`, `cached`, `live`), `timeout_minutes`. `usage`: `stale_minutes`, `session_file_limit` (required positive integer, tracked value 8; all candidate files are compared by row time), `cache_warn_ratio`, `antigravity_command` (`null` or one executable path; a shim is allowed here), `command_timeout_seconds`. `extra_deny_paths` entries are absolute or relative to the project root. `extra_write_paths` entries must stay inside the project after resolving links and must neither equal nor be ancestors/descendants of any denied path. Absolute paths, traversal, ambiguous Windows aliases/streams and denied link aliases are refused; only the validated grants are accepted by the argv grammar. `--model`, `--effort` and `--timeout-minutes` on `start` override the role. Effort is never lowered to save quota. Refused at start: effort `ultra`, the fast tier (`service_tier`), `--dangerously-*`, `--sandbox`/`-s`, `sandbox_mode`, `danger-full-access`, and Claude-only flags (`--cache-ttl`, `--ctx-nudge`, `--autocompact-window`, `--mcp`, `--advisor`, `--git-guard`). The launcher never edits `~/.codex/config.toml`; [codex_home.example.toml](codex_home.example.toml) is a reference only.

**Permissions.** Every `exec` and `resume` passes the whole profile through `-c` (an inline `permissions.<name>.filesystem` table that extends `:workspace` and denies `.secrets`, `<codex home>/auth.json`, the `.secrets` of this root, of the main checkout when the root is a worktree, and of the worker's cwd, and `extra_deny_paths`). `-s`/`--sandbox` is never passed because it replaces `default_permissions`. **The whole assembled argv is checked** by a fail-closed grammar (`check_argv`: only the launcher's flags, every `-c` key with its exact value shape, no repeated key or flag, the profile keys matching `default_permissions`, the prompt marker last), so no equivalent spelling (`--config=`, `-sread-only`, `--sandbox=...`) passes. **The fast tier is pinned off on every call**: `-c service_tier="default"` and `-c features.fast_mode=false`, so an ambient setting of `~/.codex/config.toml` cannot apply (`features.fast_mode` verified offline with `codex features list`; the `service_tier="default"` value is the documented name of Standard and is awaiting the PM's live check). The prompt goes in by stdin (`-`), never argv; the session id is captured from the `--json` `thread.started` event; `send` runs `codex exec resume <thread>` (never `--last`) with the worktree as cwd. The child environment is an allowlist (`ENV_ALLOWLIST` plus `env_allow`); credential-like names (`KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH`, `ANTHROPIC`, `OPENAI`) are never passed, so `ANTHROPIC_*` never reaches Codex.

**Fail-closed startup check.** Before the first turn, and before anything is registered, `codex sandbox` with the same profile reads the tracked `.secrets/README.md` (the only file it ever touches under `.secrets/`) and must be denied; a control read of an allowed file through the identical reader must succeed, and the profile must list `auth.json` and every protected `.secrets` directory. **The verdict never reads error text** (it varies with locale and shell). Evidence is: the host sees the file exist, the control read worked, and the denied read ended non-zero with empty stdout. With the configured project venv the reader is a host-written script run as `python -I -S reader.py <path>` whose exit code names the exception class (77 `PermissionError`, 66 `FileNotFoundError` for a file the host still sees, i.e. hidden by the deny, 74 other `OSError`); only 77 and 66 count, so a reader failure, a sandbox error or a crash of codex itself (any other code), a spawn failure or a timeout refuses the start. Both platforms use the same typed script under the configured project venv interpreter; startup failures require the user-owned base interpreter read-only grant, never an agent permission change. There is no plain-reader fallback. Any unrelated I/O error after a successful control read remains inconclusive. **Not probed:** the `auth.json` deny is checked structurally only (the file is never read). The live behaviour of `codex sandbox` with these readers is `not_run`.

**Turns, usage and ledger.** Each turn appends one JSONL row to `.tmp/pm-state/worker-ledger.jsonl` (Claude turns too): `time`, `task`, `worker`, `backend`, `model`, `effort`, `turn`, `seconds`, status, `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens` and the usage windows before and after. Codex reports cumulative usage on a resumed thread, so the ledger stores the difference to the previous turn. A turn that ended without a usage object (a failed turn) leaves its tokens in the next cumulative total, so the registry counts it (`codex_usage_gap`) and the next row is labelled `usage_basis: aggregate` with `unreported_turns_included` (it holds those turns too, and raises no cache warning); other rows say `first-turn`, `delta`, `reported-not-cumulative` or `none`. ## Context policy

User decision 2026-10-10: workers compact near 200K tokens, and a nudge at 170K asks them to write their state into the task file first, so compaction loses nothing. - **Mechanism:** `CLAUDE_CODE_AUTO_COMPACT_WINDOW=<N>` in that worker's child process only. Verified in the installed binary (`claude` 2.1.296): the string exists and its message says it "takes precedence" over the `autoCompactWindow` setting, so it also beats an ambient value or the user's setting. Skipped, only when the **consumer is a known data command** (`DATA_CONSUMERS`: `cat`, `echo`, `printf`, `tee`, `sed` without the `e`/`w` command or flag, `head`, `grep`, `git`, `gh`, `Set-Content`, `Out-File`, ...) or an interpreter (`python*`, `node`, `perl`, `ruby`, ...): bash heredoc and `<<<` bodies, PowerShell here-strings and strings piped on. Also skipped: comments (`#`, `<# #>`), PowerShell here-strings, the quoted arguments of data commands (`echo`, `printf`, `cat`, `sed`, `awk`, `grep`, `rg`, `git`, `python`, `node`, `Write-Output`, `Set-Content`, `Select-String`, ...; see `DATA_HEADS`) and string literals assigned to a variable. Still parsed: a body read by **any other consumer** (a shell, `source`, `.`, `eval`, `xargs`, `awk`, `ssh`, `iex`/`Invoke-Expression`, `powershell -Command -`, `sed -e e`, an unknown command; `cat <<EOF | sh` is code because one reader in the pipeline is), `echo`/`printf`/`Write-Output` arguments piped into a shell or evaluator, `[scriptblock]::Create('...')` and `.InvokeScript('...')` literals, the command after a PowerShell assignment prefix (`$x=Stop-Process ...`, `[int]$x =`, `$env:X=`), `bash -c`, `powershell -Command`, `cmd /c`, `-EncodedCommand`, `iex`, `eval` and `Start-Process ... -ArgumentList '-Command',...` (a heredoc inside such a string is code: `bash -c "$(cat <<'EOF' ...)"` runs its body), `$(...)` and backticks inside double quotes and in unquoted-delimiter heredocs (they execute), and the quoted text of any command that is not a data command. A heredoc without a terminator line is treated as code, not hidden. The three false positives logged on 2026-10-10 (a heredoc writing a test file, a `sed` script plus heredoc, a `python - <<'EOF'` body quoting the method calls) are tracked tests, each with negative twins.
- **Limits (safety net, not a sandbox):** it does not inspect interpreter code (`python -c "os.kill(...)"`, a `python - <<'EOF'` body, `psutil`, scripts run by path; an interpreter body is skipped on purpose, otherwise the logged README-text false positive would return); command text built in a variable and run later (`$s = '...'; iex $s`) is not seen, nor is text produced by another command (`Get-Content f | iex`); wrappers with a value-taking option (`sudo -u root kill x`) are not unwrapped; the method-call patterns (`.Kill()` and its `Terminate` twin, also with a quoted method name) are caught only on `$var`, `$_`, `)`, `]` or `}` receivers, and a method name built at run time is not; PowerShell options are matched by its unique-prefix rule (`-co`, `-en`), cmd's glued `/c"..."` is read, and `Invoke-CimMethod`/`Invoke-WmiMethod` followed by `terminate` in any parameter spelling is blocked; a classifier parse failure, or nesting deeper than 4 levels, blocks when a guarded verb appears anywhere in the raw command (`LOOSE_VERB` covers every verb and method call the classifier blocks, checked by a test over all blocked examples); bad hook input passes. A worker with shell access can always do harm another way. Known open bypass classes (Gemini a2 review, P3, accepted as residuals): `powershell /c` or `/command` slash switches, `% Terminate` / `ForEach-Object -MemberName Terminate` pipelines, and the `iwmi` alias (REVIEW_GEMINI_A2.md (sibling-project archive, not copied) F-09..F-11); process substitution (`bash <(echo ...)`) is not read; AGENT-WORKFLOW-3 residuals (PM accepted after two review rounds, decision 130; both also allowed by the previous guard): assignments to indexed or keyed targets (`$arr[0] = Stop-Process ...`, `$hash['k'] = ...`) and the fully qualified `[System.Management.Automation.ScriptBlock]::Create(...)` (REVIEW_GEMINI_WFTOOLS3_A2.md (sibling-project archive, not copied) NF-01, NF-02), plus text built in a variable or produced by another command before `iex` (`$s=...; iex $s`, `Get-Content f | iex`).
- Verified: a live haiku worker through `cli_worker.py` had a name-based kill blocked (nothing was killed) and the model received the reason. Not run: the Linux interpreter branch of `venv_python()`. CI: `.github/workflows/agent-workflow-ci.yml` (Ubuntu; pushes to `main` and pull requests touching `tools/agent-workflow/**` or `.claude/**`) runs Ruff on this directory, the guard and process-guard tests and `eol_check.py`; the other tests here run locally only.

## Context audit

`python -B -I tools/agent-workflow/context_audit.py [--worker NAME | --log FILE] [--usage-logs N] [--out FILE] [--json]` reads the first `system/init` event and first call of a worker log and reports
measured first-call tokens, loaded plugins, skills, agents, MCP servers and tools, estimated cost per plugin (4 characters per token, an assumption) and plugins with no recorded use.
It changes nothing; turning plugins or connectors off is the user's decision.

## Evaluation method

`workflow_metrics.py` treats one registry worker as one task and reads `.tmp/pm-state/cli-workers.json` plus `.tmp/cli-jobs/*/*.jsonl`.

| Column | Meaning |
|---|---|
| First call | Input + cache read + cache write tokens of the first call (fixed start cost) |
| Input-eq | Sum of input x1 + cache read x0.1 + cache write x2 (`--read-weight`, `--write-weight`) |
| Cost USD | Largest `total_cost_usd` (cumulative per session; checked on a two-turn worker) |
| Resume / call miss, miss write | Calls whose cache read is more than 4096 tokens below the previous context; tokens they rewrote |
| Blocked | Tool results with `BLOCKED by process_guard` (guarded workers only) |
| Would-block, Nudge, Loop | The hook rules replayed on the transcript with the worker's own settings (defaults for unguarded workers), so a baseline shows what the guard would have done |

```text
# baseline: the last 10 completed unguarded workers before the guard
python -B tools/agent-workflow/workflow_metrics.py --guarded no --last 10 --until 2026-10-10T19:07:02 --out .tmp/wfguard/metrics-baseline.md
# comparison: tasks started after the guard
python -B tools/agent-workflow/workflow_metrics.py --since 2026-10-10T19:30:00 --guarded yes
# both groups in one report
python -B tools/agent-workflow/workflow_metrics.py --split 2026-10-10T19:30:00 --last 10
```

`--since` is inclusive and `--until` exclusive on the worker's `created` time; `AGENT_WORKFLOW_ROOT` points the script at another root's data (read-only).
Compare like with like (same model, effort and task kind): tasks differ far more than the hooks do, so use medians and at least 10 workers per group, and treat nudges and loop warnings as behaviour signals, not savings.
Unmeasured: output tokens, wall-clock time, and whether a nudge improved handoff quality (needs review of the handoffs).

Token lever measured: `--mcp minimal` cut the first call of a trivial haiku worker from 34.3K to 32.1K tokens (about 6%; 2K to 6K depending on the plugin and connector inventory that run) and all of Bash, PowerShell, Read, Grep, Write and Edit still worked.
It removes the allowlisted research connectors (Context7, Hugging Face search, Claude Docs read), so use it only for workers that do not need them. The PM decides per profile; the default is unchanged.

## Recall: local full-text search (decision 272)

Two ideas from the claude-mem evaluation (`.tmp/claude-mem-research/report.md`, section 7), re-implemented locally; claude-mem is not installed and no code was copied.

- **Decision index at SessionStart (idea 1).** `hooks/session_context.py --decisions N` (default 8, `0` turns it off, capped at 50, an invalid value falls back to 8) adds the newest N rows of `tasks/DECISIONS_INDEX.md` as `- <id> (<date>): <first 100 characters>` plus the search command. A missing or malformed index file leaves the index out; the agreements and budget lines are unchanged. The default needs no settings change; to change the size add `"--decisions", "12"` to the `SessionStart` entry's `args` in `.claude/settings.local.json` (PM step; [settings.example.json](settings.example.json) is unchanged because the default works without arguments).
- **Search (idea 2).** `python -B -I tools/agent-workflow/recall.py build [--memory-dir DIR] [--db PATH] [--chunk-chars N]` then `recall.py search "<words>" [--limit K]` (all words must occur; hits print as `path:line [kind] excerpt`, ranked by FTS5 bm25). The database is `.tmp/pm-state/recall.sqlite` (rebuildable, git-ignored); a full build of the current tree takes about 3 s, later builds are incremental by file mtime and size.
- **Indexed:** `tasks/DECISIONS_INDEX.md`, `tasks/archive/*.md`, `docs/note/*.md`, `tasks/STATUS.md`, `tasks/LESSONS_LEARNED.md`, `tasks/REQUIREMENTS.md` and `--memory-dir` (never guessed). Chunks are decision rows, R-rows and markdown sections (at most `--chunk-chars`, default 1500). **Limit:** `--memory-dir` must be inside the project root like every other path, so the PM memory directory under `~/.claude/projects/...` cannot be indexed in place; index a project-local copy or the PM decides otherwise (recorded as a pending decision in the task file).
- **Privacy filter (idea 4), before anything is stored:** `<private>...</private>` spans (an unterminated one runs to the end of the file), private-key blocks, `sk-`/`hf_`/`AIza`/`ghp_`/`github_pat_`/`AKIA`/`xox*-` tokens, `Bearer` headers, `api_key|secret|token|password = <12+ characters with a digit>` and long mixed-case high-entropy strings become `[REDACTED]`. The whole file is redacted first with newlines kept (so a span crossing a chunk border cannot leak and line numbers stay true), then each chunk again. A file or chunk whose redaction raises is skipped. Known false positives: long URL paths; known gap: lowercase hex digests and short secrets without a known prefix are kept. Paths are resolved (links and junctions followed) and must stay inside the project root; anything under `.secrets` is refused as a source, memory directory or database location.
- **Storage:** SQLite FTS5 when the interpreter has it (checked: the project `.venv` Python 3.12.10, SQLite 3.49.1); otherwise a plain table with `LIKE` search. A change of storage mode, schema or redactor version rebuilds the database.
- **Not adopted now:** idea 3 (per-call journal hook) would add a hook process to every tool call of every session for a summary the PreCompact snapshot and transcripts already approximate. Idea 5 (quota-aware supervisor): the premise that the quota check already exists is **not true**: `cache_check.py` measures prompt-cache misses and `usage_breakdown.py` token totals per model; neither reads account quota or rate-limit state, and no tool here does. It stays a candidate if the user wants quota-based pausing (needs a verified source for the usage figure first).

## Session memory hooks (decision 353)

Every threshold, size and name is a required field of [memory_hooks.json](memory_hooks.json), validated by `memory_hooks_config.py` (bool, text, out-of-range and unknown-field values are refused). A missing or invalid field switches off only the block that needs it and the SessionStart text says `not configured: <field> (<reason>)`. `total_inject_chars` (committed 9500) is at most 10000, the documented harness cap on hook `additionalContext`, and `inbox_max_chars` is at most 9000 (the same cap minus 1,000 for the nudge and loop lines); both maxima are protocol-bound. Every other validator is a minimum. A missing or broken file never removes the base injection: the agreements, `## IN-FLIGHT` and `## NOW` still arrive (headings and a cut of 8,000 characters fixed in the hook as a safety-bound fail-safe) with a `not configured` line; only the new blocks switch off.

- **IN-FLIGHT (WP-02).** The PM keeps a `## IN-FLIGHT` section in `pm-continuation.md` (running workers and tasks, open user questions, next step). PreCompact copies it, indented, into the snapshot (`inflight_snapshot_chars`; a cut says so); the snapshot's `git status` uses `precompact_git_timeout_seconds` and `precompact_git_status_lines`. PreCompact cannot inject context, so SessionStart injects the section from the note itself (`inject_headings`, `note_inject_chars`, committed 8000 as approved). When the total leaves less room than `note_inject_chars` a `configuration problems` line says so; lower blocks are dropped first and a cut of the note is named.
- **Branches and worktrees (WP-07).** SessionStart runs read-only `git branch --no-merged <batch_branch>` and `git worktree list --porcelain` (shared deadline `git_timeout_seconds`, `GIT_OPTIONAL_LOCKS=0`, at most `max_branch_lines` and `max_worktree_lines` lines, then `... N more`; worktrees on an unmerged branch come first, then the rest with the last registered first). A timeout, a missing git or an unknown branch prints `unavailable (reason)`. Options checked on git 2.55.0.windows.3.
- **Settled index (WP-09, WP-10).** `recall.py build --settled` writes `.tmp/pm-state/settled.md` from the decision index and its numbered archives: `keywords | decision | first words of the rule`, newest first, rows replaced by a later row are dropped (only `replaces|supersedes|amends [decision] N` whose id list ends the clause with `.`, `,`, `;`, `:`, `(` or the end of the cell counts, so "replaces 2 flaky tests" removes nothing; `188` never names `188a` or `188b`), a partial `N(k)` reference annotated, redacted, at most `settled_max_chars`. SessionStart injects its first `settled_head_chars`. The newest decisions index follows `decisions_default`, `decisions_max` and `decision_text_chars` (`--decisions N` is capped by `decisions_max`). Limit: the line is the start of the rule, so some rows open with boilerplate; use `recall.py search` for detail.
- **Budget.** Blocks are added in priority order (note, configuration problems, pending decisions, branches and worktrees, settled head, newest decisions, document budgets); a block that does not fit is cut with `[cut: ...]` or named as `[not injected: ...]`, and the note is never cut by a lower block. Email-like text becomes `[email]`.
- **Applied marker (WP-15).** From `applied_from_decision` on, a decision row ends a cell with exactly one marker, `applied: <path>[, <path>]` or `applied: pending` (`**applied:**` is accepted). Paths are relative, existing files inside the repository: a second marker, a placeholder (`none`, `todo`, `n/a`), an absolute, drive or `..` path or a missing file is an error. `python -B -I tools/agent-workflow/decisions_applied.py check [--index P] [--config P] [--root P]` exits 1 for a missing, malformed or unresolved marker and 2 for an unconfigured field; SessionStart lists the `pending` ids (`pending_rows_max`) and counts bad rows. The markers are filled by the PM.
- **Turn events for the PM (WP-12).** `supervisor_events.py poll` compares `cli-workers.json` with `supervisor-events.json` and appends `- HH:MM [Step 0 ready / ]turn done: <worker> <task> (turn N)` (`Step 0 ready` when `turns` is 1; `turn ended with error: ...` for an `error` status) to `.tmp/pm-state/inbox/pm.events.md`, bounded by `inbox_max_chars` (at most 9000). `ctx_nudge.py --role pm` delivers the file once, prefixed `[supervisor-event]` and cut at 9000 characters (`PM_EVENTS_MAX_CHARS`, equal to the config maximum); `--role worker` ignores it. The first poll is a baseline. A turn that began and ended between two polls is detected by the registry `turns` counter (idle and `turns` grew; a new or restarted idle worker with `turns` >= 1 also counts). Delivery is at-most-once on the hook side (a claimed file is deleted even if the call fails) and a full inbox drops the oldest new events with a one-line count. Supervisor wiring: add `try { & $Python -B -I (Join-Path $root 'tools/agent-workflow/supervisor_events.py') poll | Out-Null } catch {}` as the first line of `Check-Cli` (one supervisor only).

Tests: `tests/unit/test_r3_memory_hooks_session.py` and `tests/unit/test_r3_memory_hooks_tools.py`; not run: a live compaction and the supervisor wiring.

## Question guard (T-AUDIT-GATES G4)

`hooks/question_guard.py` stays stateless and print-only in the committed config (`question_guard.mode: warn`, decision 503; `block` refuses, `off` disables). Besides the evidence list, a `questions` write that carries `options` is checked for:

- **S03, checked against.** `data.checked_against` (name in `checked_against_field`) must name at least one decision (`decision_pattern`, e.g. `decision 503`) and one standing rule (`rule_pattern`, `S03`), and each id must exist in `decision_files` (the index and its archives, `decision_row_pattern`) and `rules_file` (`rule_row_pattern`). An unreadable id file is a finding, never a pass.
- **S06, no repeat of a settled point.** Each option (normalised: NFKC, casefold, accents and punctuation removed, whitespace collapsed; shorter than `min_option_chars` is exempt) is compared with the options of the documents in `answered_dir` whose `status` is `answered`. A repeat is refused unless `data.reopens` lists that question's id and `data.verified` holds `user words: "<the user's words>"` (`reopen_evidence_pattern`). An unreadable answered document is a finding, and so is a JSON file that is not an object or whose `options` is not a list.
- A crash of the hook exits 0 (never blocks work); every key above is required in `guard_config.json` and validated by `hooks/guard_config.py`. Tests: `tests/test_question_guard.py` (including Hypothesis properties of the normaliser).

## Supervisor

`pm-supervisor.ps1 [-MaxMinutes 25] [-PollSeconds 60] [-StallMinutes 30] [-CliStallMinutes 60] [-ExitOnEvent] [-Python <path>] [-Companion <path>] [-HeartbeatFile pm-supervisor.json]` writes its heartbeat (PID and creation time) to `.tmp/pm-state/<file>` for `pm_invariants.py` (must equal `supervisor_heartbeat_file`) and removes it at exit; it prints one line per event and exits 0 when `-MaxMinutes` elapsed or, with `-ExitOnEvent`, after the first event. Agent jobs come from `.tmp/pm-state/agents.json`; CLI workers come from `cli_worker.py status --all --json`, run through the project `.venv` interpreter (`-Python` overrides it) with a 45 s bound. Events: `dead_launcher` (busy, launcher process gone), `stalled` (busy, log idle for `-CliStallMinutes`; `0` disables), `finished` (busy to idle or error). A persistent fault (`cli_watch_unavailable`, `cli_status_timeout`, `cli_status_failed`, `cli_status_unreadable`) is reported once, not every poll. Tests need PowerShell (`tests/test_pm_supervisor.py` skips without it).
